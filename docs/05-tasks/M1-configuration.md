## SharedKernel

### M1-01. `IPAddress`
`shared` · M · зависит от: M0-05

**Сделать:** value object IPv4/IPv6 на байтах (без `String` внутри): разбор, каноническое форматирование (RFC 5952 для IPv6), семейство, `Comparable`, `Hashable`, `Sendable`, `Codable`.
**Тесты сначала:** табличные тесты разбора (валидные и невалидные строки, IPv4-mapped IPv6, зоны `%en0` отклоняются), форматирование, сравнение, кодирование. Классификация адресов перенесена в M1-02: она выражается через сети CIDR.
**Готово, когда:** все кейсы проходят; разбор не использует `inet_pton` (чистый Swift, переносимо в тесты).

### M1-02. `IPNetwork` и `IPNetworkSet`
`shared` · L · зависит от: M1-01

**Сделать:** CIDR (`адрес/префикс`) с проверкой префикса, нормализацией битов хоста, `contains(address)`, `contains(network)`, `overlaps`. Известные сети (loopback, link-local, частные, multicast) и классификация `IPAddress` через них: `isLoopback`, `isLinkLocal`, `isPrivate`, `isMulticast` (перенесено из M1-01). `IPNetworkSet` — множество сетей с операциями объединения, пересечения, вычитания и минимизации (слияние соседних блоков). Внутреннее представление — отсортированные диапазоны (горячий путь для маршрутов и правил).
**Тесты сначала:** разбор и нормализация; классификация адресов; вычитание `0.0.0.0/0 − 10.0.0.0/8`; пересечение с `AllowedIPs`; минимизация; property-тест «объединение результатов вычитания и вычитаемого равно исходному множеству» на случайных сетях.
**Готово, когда:** алгебра верна для IPv4 и IPv6; вычитание из `0.0.0.0/0` списка частных сетей даёт известный эталонный набор.

### M1-03. `NetworkPort` и `DomainName`
`shared` · S · зависит от: M0-05

**Сделать:** `NetworkPort` (1…65535; не `Port`, чтобы не конфликтовать с `Foundation.Port`); `DomainName` (ASCII/punycode, длина меток и имени, нормализация регистра и завершающей точки, `isSameOrSubdomain(of:)`). Часы (`WallClock`, `SystemWallClock`, `FixedWallClock`) уже созданы в M0-05.
**Тесты сначала:** граничные значения порта; валидные и невалидные домены; суффиксное сравнение (`a.t.me` входит в `t.me`, `at.me` — нет).
**Готово, когда:** тесты проходят, типы `Sendable`.

## TunnelConfiguration (Core)

### M1-04. Ключи WireGuard
`shared` · M · зависит от: M0-05

**Сделать:** `WireGuardKey` (32 байта, base64 и hex), `PrivateKey` (вычисление `PublicKey` через CryptoKit Curve25519), `PublicKey`, `PresharedKey`, генерация фабриками `PrivateKey.generate()` и `PresharedKey.generate()`. У `PrivateKey` и `PresharedKey` нет `description`, `debugDescription` и зеркала, раскрывающих значение; секрет доступен только через явные `base64EncodedText` и `hexEncodedText`.
**Тесты сначала:** векторы RFC 7748; неканоничный и невалидный base64, неверная длина, невалидный hex; ни одно текстовое представление (`description`, `debugDescription`, интерполяция, `dump`) не содержит ключ.
**Готово, когда:** публичные ключи совпадают с векторами RFC 7748 (те же значения выдаёт `wg pubkey`).

### M1-05. Value objects интерфейса и пира
`shared` · M · зависит от: M1-02, M1-03

**Сделать:** `MTU` (576…9000), порт прослушивания — `NetworkPort` из SharedKernel, `PersistentKeepalive` (1…65535 секунд; `0` и `off` означают «выключено» и дают `nil`), `Endpoint` (`host:port`, IPv6 в скобках, доменное имя), `DNSConfiguration` (строка wg-quick `DNS` смешивает адреса и домены поиска — разделить), `AllowedIPs` (сети в порядке записи и нормализованное `IPNetworkSet`). В SharedKernel `CanonicalDecimalText` становится публичным: все числа в конфиге разбираются одинаково строго.
**Тесты сначала:** табличные тесты разбора и форматирования каждого типа, включая `[::1]:51820`, `vpn.example.com:51820`, порт вне диапазона.
**Готово, когда:** каждый тип отклоняет невалидный ввод доменной ошибкой с указанием причины.

### M1-06. Агрегат `TunnelConfiguration`
`shared` · S · зависит от: M1-04, M1-05

**Сделать:** `InterfaceConfiguration`, `PeerConfiguration`, `TunnelConfiguration` с инвариантами: ровно один интерфейс, уникальные публичные ключи пиров. Предупреждения (не ошибки): ноль пиров, у интерфейса нет адресов, публичный ключ пира совпадает со своим, у пира нет `AllowedIPs`. Пир в предупреждении определяется публичным ключом: он уникален, а позиция может измениться.
**Тесты сначала:** нарушение каждого инварианта; список предупреждений для пограничных конфигов.
**Готово, когда:** невалидный агрегат создать нельзя, предупреждения доступны списком.

### M1-07. Парсер wg-quick
`shared` · L · зависит от: M1-06

**Сделать:** `WgQuickConfigurationParser`: секции и ключи без учёта регистра, `#`-строки и пустые строки, многозначные ключи (`Address`, `DNS`, `AllowedIPs` через запятую и повтором), CRLF и BOM, лимит размера (64 КБ). Результат — `TunnelConfiguration` + список `ConfigurationIssue` (ошибки и предупреждения с номером строки). wg-quick-ключи `PreUp`, `PostUp`, `PreDown`, `PostDown`, `Table`, `SaveConfig`, `FwMark` → предупреждение «не поддерживается, будет проигнорировано». Ключи AmneziaWG (`Jc`, `Jmin`, `Jmax`, `S1`, `S2`, `H1`…`H4`) → понятная ошибка «конфиг AmneziaWG не поддерживается». Неизвестный ключ → ошибка.
**Тесты сначала:** фикстуры в `TunnelConfigurationTestSupport/Fixtures` (Swift-литералы с тестовыми ключами; каталог `Fixtures` исключён из проверки секретов): валидные (минимальный, полный, несколько пиров, IPv6, домен в endpoint), по одной фикстуре на каждую ошибку; проверка номеров строк; конфиги реальных провайдеров (без настоящих ключей).
**Готово, когда:** все фикстуры разбираются с ожидаемым результатом; парсер не падает на случайном вводе (fuzz-тест на 10 000 итераций).

### M1-08. Сериализатор wg-quick
`shared` · S · зависит от: M1-07

**Сделать:** `WgQuickConfigurationSerializer` с каноничным выводом: порядок ключей, одна строка на многозначный ключ.
**Тесты сначала:** `parse(serialize(x)) == x` для всех валидных фикстур и для случайно сгенерированных конфигураций; snapshot каноничного вывода.
**Готово, когда:** round-trip стабилен.

### M1-09. «Исключить локальные сети»
`shared` · S · зависит от: M1-02, M1-06

**Сделать:** `PrivateNetworkExclusion`: для пира с `0.0.0.0/0` заменить маршрут по умолчанию на публичные сети без частных, multicast и зарезервированных диапазонов (тот же набор из 30 сетей, что в официальном клиенте), сохранить доступность DNS-серверов из исключённых диапазонов маршрутами /32, определить, применено ли исключение (для состояния переключателя), и восстановить исходный список при отключении.
**Тесты сначала:** эталонный набор CIDR; распознавание уже исключённого; конфиг без `0.0.0.0/0` не меняется.
**Готово, когда:** результат совпадает с официальным клиентом на эталонных конфигах.

## AppRouting (Core, модель хранения)

### M1-10. `RoutingPolicy`
`shared` · M · зависит от: M1-03

**Сделать:** `RoutingPolicy` (`mode`, `whenTunnelUnavailable`; «исключить локальные сети» хранится в `AllowedIPs`, см. M1-09), `ApplicationSelection` и `ApplicationIdentity` (каркас: signing identifiers, Team ID, путь, вид — приложение или CLI), `ServiceSelection` (идентификаторы сервисов каталога и своих сервисов), `Codable` с версией схемы. Правила: режим выбора с пустым выбором — предупреждение; режим, недоступный на текущей платформе, — ошибка загрузки с безопасным откатом на «Весь трафик».
**Тесты сначала:** кодирование и декодирование всех режимов; совместимость со старой версией схемы; откат при недоступном режиме.
**Готово, когда:** политика сериализуется стабильно и обратно совместимо.

### M1-12. Порты и сценарии библиотеки
`shared` · L · зависит от: M1-11

**Сделать:** порты `TunnelRepository`, `TunnelSecretStore`, `ArchiveWriter`, `TunnelActivityProbe` (активен ли туннель и как его остановить; реализует `TunnelConnection` в M2). Сценарии: `CreateTunnelUseCase`, `ImportTunnelsUseCase` (пакетный импорт: частичные неудачи, конфликты имён), `UpdateTunnelUseCase`, `RenameTunnelUseCase`, `DeleteTunnelUseCase` (сначала останавливает активный туннель), `DuplicateTunnelUseCase`, `ReorderTunnelsUseCase`, `ExportTunnelsUseCase` (один или все, имена файлов в архиве уникальны), `LoadTunnelsUseCase` (список в сохранённом порядке, нечитаемые записи отдельно). Метаданные (`TunnelRecord`) и текст конфига с ключами хранятся раздельно. Секрет и метаданные сохраняются согласованно: при ошибке записи одного второе откатывается.
**Тесты сначала:** каждый сценарий с фейковыми портами; откат при сбое `TunnelSecretStore`; удаление активного туннеля; импорт 3 файлов, где 1 невалиден.
**Готово, когда:** все сценарии покрыты, у фейков нет логики сверх хранения в памяти.

### M1-13. Репозиторий метаданных в App Group
`shared` · M · зависит от: M1-12

**Сделать:** `FileTunnelRecordRepository` в `TunnelLibraryInfrastructure` — actor для последовательного доступа; каталог (контейнер App Group) передаёт composition root. JSON-файл `tunnels.json`, атомарная запись (`.atomic`: временный файл и переименование), класс защиты `completeUntilFirstUserAuthentication`, версия схемы. `JSONDocumentMigrator` с цепочкой шагов обновления: текущая версия равна 1 + число шагов, поэтому пропустить шаг нельзя. Повреждённый документ переносится в `tunnels.corrupted-<время UTC>.json`, и библиотека начинается пустой; документ более новой версии остаётся на месте нетронутым.
**Тесты сначала:** запись и чтение во временной директории; эталонный документ версии 1 читается и записывается с той же структурой; повреждённый файл → `corruptedData` и резервная копия; запись, не прошедшая валидацию, считается повреждением; документ новой версии → `unsupportedSchemaVersion` без изменения файла; нечитаемый или незаписываемый путь → `unavailable`; цепочка миграций 1 → 2 → 3 на синтетических шагах.
**Готово, когда:** данные переживают перезапуск, а повреждение не приводит к молчаливой потере.

### M1-14. Хранилище секретов в Keychain
`shared` · M · зависит от: M1-12

**Сделать:** `KeychainTunnelSecretStore` в `TunnelLibraryInfrastructure` (data protection keychain, общая access group передаёт composition root, `AfterFirstUnlockThisDeviceOnly`, `kSecAttrSynchronizable = false`): сохранить (добавление, при дубликате — обновление), прочитать, удалить конфиг по id туннеля; удаление отсутствующего не считается ошибкой. **Тесты сначала:** интеграционные тесты в `IntegrationTests`, таргет `iOSIntegrationTests` с хост-приложением `iOSApp` (нужны entitlements; `check.sh` прогоняет их на симуляторе iPhone): запись, перезапись, удаление, чтение отсутствующего, атрибуты доступности и синхронизации. Таргет для macOS добавляется после M0-04: data protection keychain на macOS требует профиля с Team ID.
**Готово, когда:** тесты проходят на симуляторе iOS и на macOS.
