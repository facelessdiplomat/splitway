## Назначение

Политика маршрутизации туннеля: что идёт через туннель (весь трафик, выбранные приложения или выбранные сервисы) и что делать с трафиком, когда туннель недоступен. Для прозрачного прокси macOS фича решает судьбу каждого потока: в туннель, напрямую или заблокировать. Слой `Presentation` даёт секцию «Маршрутизация» для редактора туннеля.

## Принцип работы

- **Политика.** `RoutingPolicy` — режим `RoutingMode` (`allTraffic`, `selectedApplications(ApplicationSelection)`, `selectedServices(ServiceSelection)`) и поведение `TunnelUnavailableBehavior` (`block` или `bypass`). По умолчанию — весь трафик и блокировка (решение D-06). Политика помнит выбор каждого режима (`applicationSelection`, `serviceSelection`), а `mode` строится из активного: после «Весь трафик» и возврата выбор на месте, в том числе после сохранения (решение D-37). `switchingMode(to:)`, `replacingApplicationSelection(with:)` и `replacingTunnelUnavailableBehavior(with:)` меняют одно и сохраняют остальное.
- **Выбор.** `ApplicationSelection` хранит `ApplicationIdentity` (вид, имя, путь, идентификаторы подписи, команда, версия бандла) без повторов по пути; `ServiceSelection` — `ServiceIdentifier` без повторов. `ApplicationIdentity` хранит путь без `/` на конце: путь папки бандла (`/Applications/Telegram.app/`) и путь из сохранённых данных приводятся к одному виду, и правило пути `ApplicationMatcher` покрывает исполняемые файлы внутри бандла.
- **Платформа.** `RoutingPlatform` знает поддерживаемые режимы: на macOS — весь трафик и приложения, на iOS и iPadOS — весь трафик и сервисы. `resolved(on:)` заменяет неподдерживаемый режим на весь трафик и сообщает, какой режим был заменён (`ResolvedRoutingPolicy`).
- **Предупреждения.** `warnings` сообщает о пустом выборе приложений или сервисов: такой туннель не пропустит через себя ничего.
- **Хранение.** `RoutingPolicy` кодируется в JSON с `schemaVersion`; чужая версия — ошибка декодирования. Выбор активного режима пишется всегда и обязателен при чтении, выбор неактивного — только непустой. Документ без него читается с пустым выбором, а старые сборки лишний ключ пропускают, поэтому версия схемы осталась первой.
- **Секция.** `RoutingSectionModel` показывает режимы платформы в постоянном порядке, переключает режим, не теряя выбор приложений или сервисов при возврате (выбор живёт в политике и сохраняется вместе с ней), показывает число выбранного и предупреждения. Вопрос «Блокировать, если туннель недоступен» задаётся только на macOS. `applicationSelection` и `setApplications(_:)` дают листу выбора приложений текущий выбор и принимают новый; новый выбор сразу попадает в политику, даже если активен другой режим. Кнопку «Выбрать приложения…» секция показывает, если редактор передал действие `chooseApplications`, а «Выбрать сервисы…» — если передал `chooseServices`. `RoutingSection` — секция формы; переключатель «Исключить локальные сети» в неё передаёт редактор, потому что он меняет `AllowedIPs` конфигурации. `RoutingPlatform.current` выбирает платформу сборки.

**Решение по потоку** (режим «Только выбранные приложения» на macOS):

- `SourceApplication` — что известно о процессе-источнике: signing identifier, Team ID, путь исполняемого файла; любое поле может отсутствовать. Если код процесса уже не прочитать, вместо них есть только непроверенный identifier из метаданных потока (`unverifiedSigningIdentifier`). `launchers` — процессы, которые его запустили, ближайший первым.
- `ApplicationMatcher` строится из выбранных приложений:
  - словарь «signing identifier → допустимые Team ID» даёт поиск за O(1);
  - отсортированные правила путей охватывают исполняемые файлы внутри выбранного бандла (хелперы, `Contents/Helpers`) и CLI-утилиты по точному пути; соседний путь вроде `Browser.app Tools` не охватывается;
  - совпадение по identifier требует того же Team ID, что у выбранного приложения, а выбранное без Team ID (Apple, неподписанные) требует процесса без Team ID. Так приложение другой команды не выдаст себя за выбранное;
  - правило пути у приложения с Team ID требует того же Team ID;
  - процесс совпадает, если по этим правилам совпадает он сам или любой процесс из `launchers` (решение D-35): так выбранное приложение забирает всё, что запустило;
  - непроверенный identifier совпадает с любым выбранным приложением с таким identifier, но только у источника без проверенного identifier и пути. Он может лишь добавить совпадение, то есть отправить поток в туннель или заблокировать его.
- `FlowDescriptor` — источник, адресат (`FlowDestination`: адрес или имя), порт и транспорт.
- `FlowRoutingDecider` строится из `RoutingPolicySnapshot` и даёт `FlowRouteDecision`:
  1. Невыбранное приложение — `.direct`.
  2. Адрес вне сетей туннеля — `.direct`.
  3. Туннель недоступен (`TunnelReadiness.unavailable`) — `.block` или `.direct` по `TunnelUnavailableBehavior`.
  4. IPv6-адрес, а туннель IPv6 не несёт — `.block`, чтобы трафик выбранного приложения не ушёл мимо туннеля.
  5. Иначе — `.tunnel`. Адресат-имя (`remoteHostname`) идёт в туннель: имя резолвится через DNS туннеля (M4-07).
- `RoutingPolicySnapshot` — выбранные приложения, сети туннеля и поведение без туннеля для передачи в системное расширение. Он кодируется в JSON с `schemaVersion`; чужая версия — ошибка. Сети туннеля передаёт сессия прокси (M4-11): `AllowedIPs` после «исключить локальные сети» и с `2000::/3` по решению D-30.

## Публичный API

`RoutingPolicy`, `RoutingMode`, `RoutingModeKind`, `TunnelUnavailableBehavior`, `RoutingPlatform`, `ResolvedRoutingPolicy`, `RoutingPolicyWarning`, `ApplicationSelection`, `ApplicationIdentity`, `ApplicationIdentityError`, `ApplicationKind`, `ServiceSelection`, `ServiceIdentifier`, `ServiceIdentifierError`; решение по потоку — `SourceApplication`, `ApplicationMatcher`, `FlowDescriptor`, `FlowDestination`, `FlowTransport`, `FlowRoutingDecider`, `FlowRouteDecision`, `TunnelReadiness`, `RoutingPolicySnapshot`; экран — `RoutingSectionModel`, `RoutingSection`, `RoutingModeKind.title`, `RoutingPlatform.current`.

## Решения

- Названия режимов (`RoutingModeKind.title`) живут здесь и используются и списком туннелей, и редактором.
- Секция не выбирает приложения сама: лист выбора (фича `ApplicationCatalog`) открывает редактор, а секция только показывает кнопку, число выбранного и предупреждение о пустом выборе. Так `AppRouting` не зависит от каталога приложений. Экран выбора сервисов — M5-07.

## Спорные решения

| Решение | Альтернативы | Почему так | Когда пересмотреть |
|---|---|---|---|
| Выбор приложений и сервисов запоминается при переключении режимов, в том числе после сохранения (решение D-37), и хранится в `RoutingPolicy` | Сбрасывать выбор; хранить выбор неактивного режима в `Tunnel` отдельно от политики | Пользователь может проверить «Весь трафик» и вернуться, не собирая список заново. Выбор — часть политики: он кодируется вместе с ней, а расширение и решение по потоку читают только `mode`. Отдельное хранение разнесло бы одно понятие по двум фичам | Нет |
| Число выбранного — строка с формами множественного числа в каталоге | Автоматическое согласование `inflect` | Автоматическое согласование не поддерживает русский | Если Foundation начнёт склонять русский |
| Выбранное без Team ID совпадает только с процессом без Team ID | Совпадение по одному signing identifier | Приложение с Developer ID не выдаст себя за утилиту Apple. Identifier ad-hoc кода `SourceApplicationResolver` (`TransparentProxy`, M4-09) не передаёт: без Team ID доверяется только код с подписью Apple | Нет |
| Непроверенный identifier процесса, код которого уже не прочитать, совпадает с выбранным приложением | Не доверять identifier без Team ID и пути | Код короткоживущего процесса часто не успевает прочитаться (SP-2), и его поток уходил напрямую. В режиме «Только выбранные приложения» совпадение отправляет поток в туннель или блокирует его, так что чужой процесс с подставным identifier не выйдет напрямую мимо правил | Режим «Все, кроме выбранных» (D-05): там совпадение значит «напрямую», и непроверенному identifier верить нельзя |
| Снимок хранит `ApplicationIdentity` целиком | Отдельная урезанная форма | Типы уже проверены и кодируются; имя и вид занимают десятки байт | Если снимок станет большим |
| Порт и транспорт не участвуют в решении | Правила по портам | В v1 выбор только по приложению и адресу | Если появятся правила по портам |

## Ограничения и известные проблемы

- Пакетный туннель принимает только режим «Весь трафик»: «Только выбранные приложения» на macOS работает через прозрачный прокси (M4), выбор сервисов — M5.
- Экран выбора сервисов — M5-07.
- Выделения памяти на горячем пути проверены в Instruments (Allocations, `xctrace`) на Mac разработчика 2026-10-31: тест производительности (миллион решений) в release-сборке выделяет за весь прогон 7 264 блока, из них временных 4 821, — это запуск тестов, а не решения; миллион решений занимает 0,043 с. В отладочной сборке решение выделяет около 4 блоков на вызов (4 004 979 временных): без оптимизации Swift выделяет контексты замыканий в `ApplicationMatcher`. Выпускная сборка расширения — release, поэтому у пользователей на горячем пути выделений нет; сборки разработки (Debug) их делают.

## Тесты

- 31 тест в `AppRoutingTests`:
  - выбор без повторов, предупреждения, разрешение режима по платформе, кодирование и версия схемы;
  - смена режима и поведения без туннеля не теряет выбор, выбор неактивного режима в JSON и при чтении;
  - решение по потоку — табличный тест на 25 случаев: выбранное и невыбранное приложение, хелпер, подмена identifier и Team ID, адрес вне сетей туннеля, недоступный туннель с блокировкой и без, IPv6 без IPv6 в туннеле, CLI по пути, исполняемый файл внутри бандла и рядом, адресат-имя, процесс, запущенный выбранным приложением напрямую, через оболочку и через хелпер, агент вне бандла сам по себе, процесс, запущенный невыбранным приложением или подменой;
  - снимок: кодирование туда и обратно, чужая версия схемы, сборка из политики;
  - производительность: миллион решений меньше чем за 5 секунд в отладочной сборке; выделения памяти этого теста проверены в Allocations (раздел «Ограничения»);
  - версия бандла в идентичности: кодирование и чтение старых записей без неё;
  - путь без `/` на конце: путь папки бандла, исполняемый файл бандла, выбранного по такому пути, путь из одних `/`.
- 12 тестов в `AppRoutingPresentationTests`: режимы macOS и iOS, неподдерживаемый режим, предупреждение о пустом выборе, выбор после переключения режимов, блокировка по умолчанию, вопрос о недоступном туннеле только на macOS, замена выбранных приложений и выбор, сделанный до переключения режима, выбор туннеля, сохранённого с «Весь трафик», и выбор в политике после смены режима и поведения без туннеля.

`AppRoutingTestSupport` отдаёт `FlowRoutingFixtures`: выбранный браузер и его хелпер, подмены, CLI-утилиты и снимок политики. Ими пользуются тесты `AppRouting` и `DNSProxy`.

Запуск: `swift test --package-path Packages/SplitwayKit --filter AppRouting`.
