## Назначение

Установка и обновление системного расширения macOS, в котором работают пакетный туннель, прозрачный прокси и DNS-прокси. Фича решает, заменять ли уже активное расширение, объясняет, почему активация не удалась, и ведёт пользователя через одобрение расширения в Системных настройках.

## Принцип работы

1. `EnsureSystemExtensionActivatedUseCase` отправляет запрос активации через порт `SystemExtensionActivator` и превращает события в состояния: `activating` → `awaitingUserApproval` → `activated`, `requiresReboot` или `failed(reason)`.
2. Делегат `ActivationRequestDelegate` отвечает на `actionForReplacingExtension` по `ExtensionReplacementPolicy`:
   - версии `CFBundleVersion` различаются → заменить: обновление или откат приложения, расширение должно совпадать с протоколами приложения;
   - совпадают → оставить работающее, не разрывая VPN;
   - нечитаемая версия → заменить.
3. Ответ `.cancel` при равных версиях система сообщает ошибкой `requestCanceled`. Делегат превращает её в «уже активно», а не в отказ.
4. `SystemExtensionErrorMapping` переводит `OSSystemExtensionError` в причины: приложение не в «Программах», повреждённая установка, запрет политикой, нужна авторизация, запрос отменён.

**Мастер одобрения** (`SystemExtensionPresentation`).

- `SystemExtensionWizardStep` — шаг мастера для каждого `SystemExtensionState`: знакомство, установка, ожидание одобрения, готово, нужна перезагрузка, ошибка с причиной. `needsAttention` говорит, что пользователю нужно действовать: одобрить, перезагрузить Mac или повторить.
- `SystemExtensionWizardModel.install()` запрашивает активацию и переводит мастер по состояниям до конца запроса. Пока пользователь одобряет расширение в Системных настройках, мастер ждёт; после одобрения он сам переходит к «Расширение готово». Повторный вызов во время запроса ничего не делает, а после ошибки запускает мастер заново.
- `SystemExtensionWizardView` показывает шаг и его кнопку: «Установить», «Открыть Системные настройки» (раздел «Объекты входа и расширения»), «Повторить». Тексты ошибок объясняют, что сделать: переместить приложение в «Программы», скачать заново, обратиться к администратору, ввести пароль.
- `View.systemExtensionAttention(_:isSuppressed:)` открывает мастер листом при запуске, если активация требует действия пользователя. «Позже» откладывает его до следующего запроса. Во время онбординга лист не показывается: мастер работает внутри онбординга (фича `Onboarding`).

## Публичный API

`BundleVersion`, `ExtensionReplacementPolicy`, `ExtensionReplacementAction`, `SystemExtensionState`, `SystemExtensionActivationEvent`, `SystemExtensionFailure`, `SystemExtensionActivator`, `EnsureSystemExtensionActivatedUseCase`; адаптеры `OSSystemExtensionActivator`, `SystemExtensionErrorMapping`; мастер — `SystemExtensionWizardModel`, `SystemExtensionWizardStep`, `SystemExtensionWizardView`, модификатор `systemExtensionAttention(_:isSuppressed:)`.

## Решения

- `BundleVersion` сравнивает числовые компоненты через точку, недостающие компоненты считаются нулём: `1` = `1.0.0`, `1.10` > `1.9`.
- Адаптеры собираются только для macOS (`#if os(macOS)`), а Core платформенно-независим.

## Спорные решения

| Решение | Альтернативы | Почему так | Когда пересмотреть |
|---|---|---|---|
| Заменять и при откате на старую версию | Заменять только на новую | Расширение всегда совпадает с протоколами приложения; версионированные сообщения не спасут рабочий туннель от несовместимости | Нет |
| Равные версии → оставить работающее | Всегда заменять | Замена перезапускает расширение и рвёт VPN без пользы | Если сборки с одинаковой версией начнут различаться |
| Имя фичи `SystemExtension` рядом с фреймворком `SystemExtensions` | Другое имя | Имя из плана и архитектуры; модули различаются окончанием | Если путаница начнёт мешать |
| Активация запрашивается при каждом запуске после онбординга | Только при первом запуске | Так расширение заменяется после обновления приложения, а отозванное одобрение снова приводит к мастеру | Нет |
| Мастер открывает раздел «Объекты входа и расширения» ссылкой `x-apple.systempreferences:` | Только текстовая инструкция | Одна кнопка вместо поиска раздела; текст на шаге всё равно называет путь | Если Apple изменит адрес раздела |

## Ограничения и известные проблемы

- Установка, одобрение пользователем и замена при обновлении проверяются только с подписью Developer ID на чистой системе.
- Приложение macOS запрашивает активацию при запуске и показывает мастер; живой путь одобрения проверяется только с подписью Developer ID (M0-04).

## Тесты

- 6 тестов в `SystemExtensionTests`: разбор и сравнение версий, решение о замене (новая, та же, старая, нечитаемая), последовательности состояний активации.
- 2 теста в `SystemExtensionInfrastructureTests`: соответствие кодов `OSSystemExtensionError` и чужие ошибки.
- 7 тестов в `SystemExtensionPresentationTests`: шаг для каждого состояния, где нужен пользователь, знакомство до установки, переход дальше после одобрения, один запрос во время активации, повтор после ошибки, «Позже».
- Фейки в `SystemExtensionTestSupport`: `ScriptedSystemExtensionActivator` (готовые последовательности событий для каждого запроса) и `ControlledSystemExtensionActivator` (события по команде теста).
