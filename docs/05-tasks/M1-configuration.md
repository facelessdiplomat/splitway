## SharedKernel

### M1-01. `IPAddress`
`shared` · M · зависит от: M0-05

**Сделать:** value object IPv4/IPv6 на байтах (без `String` внутри): разбор, каноническое форматирование (RFC 5952 для IPv6), семейство, классификация (loopback, link-local, private, multicast), `Comparable`, `Hashable`, `Sendable`, `Codable`.
**Тесты сначала:** табличные тесты разбора (валидные и невалидные строки, IPv4-mapped IPv6, зоны `%en0` отклоняются), форматирование, классификация, сравнение.
**Готово, когда:** все кейсы проходят; разбор не использует `inet_pton` (чистый Swift, переносимо в тесты).

### M1-02. `IPNetwork` и `IPNetworkSet`
`shared` · L · зависит от: M1-01

**Сделать:** CIDR (`адрес/префикс`) с проверкой префикса, нормализацией битов хоста, `contains(address)`, `contains(network)`, `overlaps`. `IPNetworkSet` — множество сетей с операциями объединения, пересечения, вычитания и минимизации (слияние соседних блоков). Внутреннее представление — отсортированные диапазоны (горячий путь для маршрутов и правил).
**Тесты сначала:** разбор и нормализация; вычитание `0.0.0.0/0 − 10.0.0.0/8`; пересечение с `AllowedIPs`; минимизация; property-тест «объединение результатов вычитания и вычитаемого равно исходному множеству» на случайных сетях.
**Готово, когда:** алгебра верна для IPv4 и IPv6; вычитание из `0.0.0.0/0` списка частных сетей даёт известный эталонный набор.

### M1-03. `Port` и `DomainName`
`shared` · S · зависит от: M0-05

**Сделать:** `Port` (1…65535); `DomainName` (ASCII/punycode, длина меток и имени, нормализация регистра и завершающей точки, `isSubdomain(of:)`). Часы (`WallClock`, `SystemWallClock`, `FixedWallClock`) уже созданы в M0-05.
**Тесты сначала:** граничные значения порта; валидные и невалидные домены; суффиксное сравнение (`a.t.me` входит в `t.me`, `at.me` — нет).
**Готово, когда:** тесты проходят, типы `Sendable`.

## TunnelConfiguration (Core)

### M1-04. Ключи WireGuard
`shared` · M · зависит от: M0-05

**Сделать:** `WireGuardKey` (32 байта, base64 и hex), `PrivateKey` (вычисление `PublicKey` через CryptoKit Curve25519), `PublicKey`, `PresharedKey`, `KeyPairGenerator`. У `PrivateKey` нет `description` и `debugDescription`, раскрывающих значение.
**Тесты сначала:** векторы RFC 7748; пары ключей, сгенерированные утилитой `wg` (фикстуры); невалидный base64, неверная длина; `String(describing: privateKey)` не содержит ключ.
**Готово, когда:** публичный ключ совпадает с `wg pubkey` на всех фикстурах.

### M1-05. Value objects интерфейса и пира
`shared` · M · зависит от: M1-02, M1-03

**Сделать:** `MTU` (576…9000), `ListenPort`, `PersistentKeepalive` (0…65535, 0 = выключено), `Endpoint` (`host:port`, IPv6 в скобках, доменное имя), `DNSConfiguration` (строка wg-quick `DNS` смешивает адреса и домены поиска — разделить), `AllowedIPs` (обёртка над `IPNetworkSet`).
**Тесты сначала:** табличные тесты разбора и форматирования каждого типа, включая `[::1]:51820`, `vpn.example.com:51820`, порт вне диапазона.
**Готово, когда:** каждый тип отклоняет невалидный ввод доменной ошибкой с указанием причины.

### M1-06. Агрегат `TunnelConfiguration`
`shared` · S · зависит от: M1-04, M1-05

**Сделать:** `InterfaceConfiguration`, `PeerConfiguration`, `TunnelConfiguration` с инвариантами: ровно один интерфейс, уникальные публичные ключи пиров. Предупреждения (не ошибки): ноль пиров, публичный ключ пира совпадает со своим, у пира нет `AllowedIPs`.
**Тесты сначала:** нарушение каждого инварианта; список предупреждений для пограничных конфигов.
**Готово, когда:** невалидный агрегат создать нельзя, предупреждения доступны списком.

### M1-07. Парсер wg-quick
`shared` · L · зависит от: M1-06

**Сделать:** `WgQuickConfigurationParser`: секции и ключи без учёта регистра, `#`-строки и пустые строки, многозначные ключи (`Address`, `DNS`, `AllowedIPs` через запятую и повтором), CRLF и BOM, лимит размера (64 КБ). Результат — `TunnelConfiguration` + список `ConfigurationIssue` (ошибки и предупреждения с номером строки). wg-quick-ключи `PreUp`, `PostUp`, `PreDown`, `PostDown`, `Table`, `SaveConfig`, `FwMark` → предупреждение «не поддерживается, будет проигнорировано». Ключи AmneziaWG (`Jc`, `Jmin`, `Jmax`, `S1`, `S2`, `H1`…`H4`) → понятная ошибка «конфиг AmneziaWG не поддерживается». Неизвестный ключ → ошибка.
**Тесты сначала:** набор фикстур `Tests/Fixtures/wg-quick/`: валидные (минимальный, полный, несколько пиров, IPv6, домен в endpoint), по одной фикстуре на каждую ошибку; проверка номеров строк; конфиги реальных провайдеров (без настоящих ключей).
**Готово, когда:** все фикстуры разбираются с ожидаемым результатом; парсер не падает на случайном вводе (fuzz-тест на 10 000 итераций).

### M1-08. Сериализатор wg-quick
`shared` · S · зависит от: M1-07

**Сделать:** `WgQuickConfigurationSerializer` с каноничным выводом: порядок ключей, одна строка на многозначный ключ.
**Тесты сначала:** `parse(serialize(x)) == x` для всех валидных фикстур и для случайно сгенерированных конфигураций; snapshot каноничного вывода.
**Готово, когда:** round-trip стабилен.

### M1-09. «Исключить локальные сети»
`shared` · S · зависит от: M1-02, M1-06

**Сделать:** `AllowedIPsCalculator`: для пира с `0.0.0.0/0` построить `AllowedIPs` без частных и служебных сетей (тот же набор, что в официальном клиенте) и определить, применено ли уже исключение (для состояния переключателя).
**Тесты сначала:** эталонный набор CIDR; распознавание уже исключённого; конфиг без `0.0.0.0/0` не меняется.
**Готово, когда:** результат совпадает с официальным клиентом на эталонных конфигах.

## AppRouting (Core, модель хранения)

### M1-10. `RoutingPolicy`
`shared` · M · зависит от: M1-03

**Сделать:** `RoutingPolicy` (`mode`, `excludesPrivateNetworks`, `whenTunnelUnavailable`), `ApplicationSelection` и `ApplicationIdentity` (каркас: signing identifiers, Team ID, путь, вид — приложение или CLI), `ServiceSelection` (id сервисов каталога + свои правила), `Codable` с версией схемы. Правила: режим выбора с пустым выбором — предупреждение; режим, недоступный на текущей платформе, — ошибка загрузки с безопасным откатом на «Весь трафик».
**Тесты сначала:** кодирование и декодирование всех режимов; совместимость со старой версией схемы; откат при недоступном режиме.
**Готово, когда:** политика сериализуется стабильно и обратно совместимо.

## TunnelLibrary

### M1-11. `Tunnel`, `TunnelName`, уникальность имён
`shared` · S · зависит от: M1-06, M1-10

**Готово, когда:** любая строка либо превращается в валидное имя, либо даёт понятную ошибку.

### M1-12. Порты и сценарии библиотеки
`shared` · L · зависит от: M1-11

**Сделать:** порты `TunnelRepository`, `TunnelSecretStore`, `ArchiveWriter`, `TunnelActivityProbe` (активен ли туннель и как его остановить; реализует `TunnelConnection` в M2). Сценарии: `CreateTunnelUseCase`, `ImportTunnelsUseCase` (пакетный импорт: частичные неудачи, конфликты имён), `UpdateTunnelUseCase`, `RenameTunnelUseCase`, `DeleteTunnelUseCase` (сначала останавливает активный туннель), `DuplicateTunnelUseCase`, `ReorderTunnelsUseCase`, `ExportTunnelsUseCase` (один или все, имена файлов в архиве уникальны). Секрет и метаданные сохраняются согласованно: при ошибке записи одного второе откатывается.
**Тесты сначала:** каждый сценарий с фейковыми портами; откат при сбое `TunnelSecretStore`; удаление активного туннеля; импорт 3 файлов, где 1 невалиден.
**Готово, когда:** все сценарии покрыты, у фейков нет логики сверх хранения в памяти.

### M1-13. Репозиторий метаданных в App Group
`shared` · M · зависит от: M1-12

**Готово, когда:** данные переживают перезапуск, а повреждение не приводит к молчаливой потере.

## Diagnostics (Core и Infrastructure)

### M1-18. Маскирование секретов и кольцевой журнал
`shared` · M · зависит от: M1-04

**Сделать:** `LogRedactor`: вырезает значения ключей WireGuard (32 байта base64 и hex, строки `PrivateKey =` / `PresharedKey =`) из любого текста. `LogEntry` (время, уровень, источник: приложение / расширение / движок, текст). **Готово, когда:** ни одна фикстура с ключом не проходит в журнал без маски.
