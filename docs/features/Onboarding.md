## Назначение

Первый запуск приложения: что делает Splitway, обещание приватности и что спросит система. На macOS онбординг заканчивается мастером системного расширения, без которого туннель не запустится.

| Тип | Что | Зачем |

| Системные фреймворки | Foundation; в `Presentation` — SwiftUI, Observation | `UserDefaults`; экраны |
| Сторонние библиотеки | нет | |

## Принцип работы

- Порт `OnboardingRecord` помнит, пройден ли онбординг. `UserDefaultsOnboardingRecord` хранит признак в `UserDefaults` приложения: расширениям он не нужен.
- `OnboardingModel` показывает онбординг, пока он не пройден.
  - Страницы: «Добро пожаловать», «Ваши данные остаются у вас», «О чём спросит система».
  - Если composition root передал мастер системного расширения (только на macOS), четвёртая страница — мастер `SystemExtensionWizardView`.
  - «Назад» и кнопка вперёд, которую выбирает модель (`OnboardingForwardAction`): «Продолжить», «Начать» на последней странице или «Не сейчас» на странице расширения.
  - «Установить» и «Повторить» мастера идут через `installSystemExtension()`. Когда пользователь одобрил расширение и оно активно, онбординг закрывается сам.
- Тексты страниц зависят от платформы: на iOS — выбор сервисов, запрос конфигурации VPN и камера только для QR; на macOS — выбор приложений, одобрение расширения и запрос конфигурации VPN.
- `View.onboarding(_:)` показывает онбординг на весь экран на iOS и листом на macOS. Смахнуть его нельзя, закрывается он только кнопкой.
- Страница прокручивается, если на крупных размерах шрифта не помещается на экран (`OverflowScrollView`).
- `activateSystemExtensionOnLaunch()` при следующих запусках запрашивает активацию расширения, но только если онбординг уже пройден: иначе мастер работает внутри онбординга. Активация при каждом запуске заменяет расширение после обновления приложения (политика замены — в `SystemExtension`).

## Публичный API

`OnboardingRecord`; адаптер `UserDefaultsOnboardingRecord`; экран — `OnboardingModel`, `OnboardingPage`, `OnboardingForwardAction`, модификатор `onboarding(_:)`.

## Решения

- Страница расширения — часть онбординга, а не отдельный экран: новый пользователь на Mac доходит до подключения без внешних инструкций.
- Модель, а не экран, решает, какая кнопка ведёт вперёд, и закрывает онбординг после одобрения расширения.

## Спорные решения

| Решение | Альтернативы | Почему так | Когда пересмотреть |
|---|---|---|---|
| Признак «онбординг пройден» без версии | Номер версии онбординга | Нечего показывать повторно; версию легко добавить, когда онбординг заметно изменится | Когда появится новая страница для уже пройденного онбординга |
| «Не сейчас» на странице расширения | Обязательная установка | Пользователь может сначала осмотреться; при следующем запуске приложение само попросит одобрить расширение | Нет |
| Онбординг на весь экран на iOS | Лист | Первый запуск — отдельный шаг, а не временное окно поверх списка | Нет |

Нет.

## Ограничения и известные проблемы

- На macOS сборка разработки работает в тестовой ВМ, где расширение одобрено заранее, а проверки запускают её с пройденным онбордингом. Путь нового пользователя с одобрением расширения проверяется со сборкой Developer ID на чистом Mac (M3-10, M7-08): сборку разработки Mac вне профиля подписи не запустит. Одобрение расширения и автоматический переход проверены тестами моделей.
- Онбординг проверен в симуляторе iPhone на русском языке: три страницы, «Назад», «Начать», при повторном запуске онбординга нет.

## Тесты

- 1 тест в `OnboardingInfrastructureTests`: признак сохраняется в отдельном наборе `UserDefaults` и читается новым экземпляром.
- 7 тестов в `OnboardingPresentationTests`:
  - онбординг показывается, пока не пройден;
  - порядок страниц, «Назад»;
  - кнопка вперёд для каждой страницы;
  - страница расширения, когда приложению оно нужно;
  - онбординг закрывается сам после одобрения расширения и остаётся открытым при отказе;
  - активация при запуске только после пройденного онбординга.

Запуск: `swift test --package-path Packages/SplitwayKit --filter Onboarding`.
