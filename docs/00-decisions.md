| D-30 | IPv6 у туннелей только с IPv4 | **Блокировать.** В режиме «Весь трафик» туннель, который забирает весь публичный IPv4 (`0.0.0.0/0` или его форма с исключением локальных сетей), но не весь глобальный IPv6, дополнительно забирает `2000::/3`; если у интерфейса нет IPv6-адреса, он получает адрес-заглушку из ULA. Ни один пир не принимает такие пакеты, и wireguard-go их отбрасывает: на двухстековой сети IPv6 не идёт мимо туннеля, приложения переходят на IPv4. ULA и link-local остаются локальными, туннели с частью сетей (без маршрута IPv4 по умолчанию) не меняются | Не блокировать: маршруты только из `AllowedIPs`, как в официальном клиенте | M2-05 |
| D-35 | Процессы, которые запускает выбранное приложение (macOS) | **Идут через туннель вместе с ним**: всё, что выбранное приложение запустило само или через свои процессы, — например, Claude Code из Claude и команды, которые он выполняет, или команды в выбранных Терминале и VS Code. Цепочка запуска проверяется до launchd, не глубже 16 процессов. Выбор владельца 2026-10-31: при выбранном Claude вкладка Code шла мимо туннеля | Только процессы того же разработчика; только само приложение и его хелперы внутри бандла | [01](01-product.md), [03](03-platform-macos.md) §6.3, [AppRouting](features/AppRouting.md), [TransparentProxy](features/TransparentProxy.md), M4-09 |

## Замечание к D-23

У локального репозитория без удалённой копии есть риск потери истории вместе с диском. Достаточно Time Machine или приватного удалённого репозитория без CI, чтобы закрыть этот риск, не меняя принятое решение. С 2026-10-30 у репозитория есть приватная удалённая копия (`origin`), и каждая слитая задача отправляется туда.
