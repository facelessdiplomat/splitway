### M6-01. Строка меню macOS
`macOS` · M · зависит от: M3-02, M3-09

**Сделать:** фича `MenuBar`: `MenuBarModel` (туннели, состояния, активный туннель), `MenuBarExtra`: значок отражает состояние (выключен / подключение / активен / ошибка), список туннелей с переключением, режим маршрутизации активного туннеля, «Открыть Splitway», «Настройки…», «Выйти» (с вопросом, отключать ли туннель).
**Тесты сначала:** модель: значок для каждого состояния; выбор другого туннеля останавливает текущий; пункты меню при отсутствии туннелей.
**Готово, когда:** все действия выполняются из строки меню без открытия окна.

### M6-02. Настройки macOS и удаление
`macOS` · M · зависит от: M2-11, M3-13

**Сделать:** запуск при входе (`SMAppService.mainApp`); иконка в Dock видна, пока открыто окно, и скрывается после его закрытия (`DockVisibilityPolicy` + `NSApp.setActivationPolicy`, решение D-12); «Удалить Splitway»: `UninstallUseCase` останавливает туннель, удаляет системные конфигурации, секреты в обоих Keychain и данные App Group, отправляет `deactivationRequest`, затем предлагает переместить приложение в корзину.
**Тесты сначала:** `UninstallUseCase` на фейках: порядок шагов; продолжение при сбое одного шага с итоговым отчётом. `DockVisibilityPolicy`: окно открыто → иконка видна, все окна закрыты → скрыта.
**Готово, когда:** после удаления в системе не остаётся конфигураций VPN, расширения и секретов (проверка на чистой VM).

### M6-03. Команды (App Intents)
`shared` · M · зависит от: M2-09

**Сделать:** фича `Shortcuts`: `TunnelEntity` и `TunnelEntityQuery` (из репозитория App Group), `ConnectTunnelIntent`, `DisconnectTunnelIntent`, `ToggleTunnelIntent` поверх сценариев `TunnelConnection`; фразы Siri на `ru` и `en`; `AppShortcutsProvider`.
**Тесты сначала:** логика intent вынесена в сценарии и уже покрыта; тест запроса сущностей (поиск по имени, пустой список).
**Готово, когда:** туннель подключается из приложения «Команды» и голосом через Siri на iPhone и Mac.

### M6-04. Controls в Пункте управления (SP-8)
`iOS+iPadOS` · M · зависит от: M6-03

**Сделать:** спайк SP-8 (в каком процессе выполняется intent и можно ли из него управлять VPN), затем таргет `ControlsExtension` в `project.yml` и фича `ControlWidgets`: `ControlWidgetToggle` с выбором туннеля, состояние из `NEVPNStatus`, обновление при смене статуса.

**Готово, когда:** туннель включается из Пункта управления и с экрана блокировки без открытия приложения (или с открытием — по итогам SP-8; это зафиксировано в документе фичи).

### M6-05. Полировка iPadOS и macOS

### M6-06. Автоподключение по правилам сети (v1.x, решение D-08)
`shared` · L · зависит от: M2-10, M4-14

**Сделать:** фича `OnDemand`: `OnDemandPolicy` (Wi-Fi: любые / только эти SSID / кроме этих; сотовая; Ethernet на macOS), компилятор в промежуточные правила (Core) и маппинг в `NEOnDemandRule` (Infrastructure) для обоих слотов. Экран настройки в деталях туннеля. Показ текущего SSID — с разрешением на геолокацию и entitlement `wifi-info` (только если пользователь захочет).
**Тесты сначала:** компилятор: каждый вариант политики → ожидаемый набор правил и их порядок; пустая политика → автоподключение выключено.
**Готово, когда:** туннель сам включается в незнакомой Wi-Fi-сети и выключается в домашней, на iOS и macOS, в обоих режимах маршрутизации.
