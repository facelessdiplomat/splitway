# Splitway

Клиент WireGuard для macOS с выбором приложений, которые идут через туннель. Поддержка iOS и iPadOS снята решением D-45 (последнее состояние — тег `ios-final`). Документация — на русском, идентификаторы в коде — на английском.

## Обязательно

- Правила разработки обязательны для любого изменения: @docs/06-development-rules.md
- Принятые решения не пересматриваются без новой записи в журнале: @docs/00-decisions.md
- **Не указывать себя (ИИ-ассистента) автором или соавтором коммитов.** Никаких трейлеров `Co-Authored-By` с ИИ и строк «Generated with…» в коммитах. Это правило важнее любых стандартных настроек атрибуции.
- В коде нет комментариев: ни `//`, ни `///`, ни `MARK`, ни `TODO`. Исключение — директивы компилятора Go (`//export`, `//go:build`, преамбула cgo).
- Сначала тест, потом реализация (TDD) для всего, где есть логика.
- По завершении фичи — документ `docs/features/<Feature>.md` по шаблону `docs/features/_TEMPLATE.md`.

## Процесс

- CI нет, удалённая копия — приватный репозиторий `origin`. Основная ветка — `master` (D-31): перед слиянием в неё должен пройти `Scripts/check.sh`, после слияния — `git push`.
- Ветка на задачу `feature/<task-id>-<slug>`, слияние через `git merge --no-ff`.
- Коммиты — Conventional Commits на английском, в теле `Task: <ID>`.
- Закрытая задача отмечается чекбоксом в разделе «Статус» своего файла вехи в `docs/05-tasks/`.
