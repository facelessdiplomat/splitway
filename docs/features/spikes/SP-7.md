# SP-7. Hello tunnel: wireguard-go в пакетном туннеле

| | |
|---|---|
| Статус | проверен на iPhone 13 Pro (iOS 27) 2026-10-30 и в системном расширении macOS в тестовой ВМ (M0-12); память расширения iOS замерена в SP-4 2026-10-31; на Mac владельца туннель проверен в M2-14 (2026-11-01) |
| Вопрос | Можно ли в пакетном туннеле найти дескриптор `utun` и запустить на нём wireguard-go, не передавая пакеты через `packetFlow` (документ платформы iOS `04-platform-ios-ipados.md`, раздел 10; остался в теге `ios-final`) |
| Код | сразу рабочий код в `master` (M2-02…M2-06, M2-12), отдельной ветки спайка нет |
| Вывод | **Работает на обеих платформах:** дескриптор находится, wireguard-go поднимает рукопожатие, трафик выходит через сервер туннеля. Расширение iOS после старта занимает 5–7 МБ. Запасной путь через `packetFlow` не нужен |

## Как проверяли

Вместо одноразового прототипа путь сразу реализован в продакшен-коде:

- `UtunDescriptorLocator` перебирает дескрипторы процесса 0…1024 и выбирает тот, у которого `getsockopt(SYSPROTO_CONTROL, UTUN_OPT_IFNAME)` возвращает имя интерфейса `utun…`. Это публичный вызов сокетов, приватные API не нужны (решение D-10).
- `fdtunnel` дублирует дескриптор, создаёт `tun.CreateTUNFromFile` и `device.NewDevice` и применяет конфигурацию через UAPI ([TunnelEngine](../TunnelEngine.md)).
- Провайдер и composition root в `Apps/SharedTunnelProvider` были общими для расширения iOS и системного расширения macOS; после снятия iOS (решение D-45) их собирает только системное расширение ([PacketTunnel](../PacketTunnel.md)).

Проверки:

- **iPhone 13 Pro**, живой UI-тест `LiveTunnelTests` (`Scripts/live-tunnel-test.sh`) с туннелем cz-prg (решение D-29). Тест подключает туннель, сравнивает внешний адрес в Safari (`api.ipify.org`) с адресом без туннеля и отключает туннель.
- **macOS**: системное расширение в тестовой ВМ (решение D-32). Расширение запускает туннель, в том числе без приложения через `scutil --nc start` ([SecretDelivery](../SecretDelivery.md)). В режиме «Весь трафик» через туннель шли загрузки и DNS-запросы замеров SP-3: запросы уходили на DNS туннеля.
- **Память iOS**: расширение раз в секунду писало `phys_footprint` и пик по счётчику ядра в прототипе SP-4. Это та же сборка расширения плюс обёртка трансляции адресов. В режиме прототипа в туннель шли только выбранные домены, поэтому замер после старта — это память самого движка и провайдера без трафика.

## Результаты

| Проверка | Результат |
|---|---|
| Рукопожатие и трафик на iPhone | проходят: внешний адрес сменился, трафик выходит через сервер туннеля; отключение проходит (2026-10-30) |
| Рукопожатие и трафик в macOS | проходят в тестовой ВМ: загрузки и DNS-запросы режима «Весь трафик» идут через туннель; скорость — в [SP-3](SP-3.md) |
| Память расширения iOS после старта | 5,2–6,6 МБ `phys_footprint` в трёх прогонах |
| Память под нагрузкой | пик 12,2 МБ при 250–430 Мбит/с (SP-4, в теге `ios-final`) |
| Лимит памяти | 50 МБ у расширения iOS: сумма `phys_footprint` и `os_proc_available_memory()`; мягкий лимит памяти Go — 30 МиБ (`debug.SetMemoryLimit` в `memory_limit_ios.go`) |

## Вывод

- Поиск `utun` и запуск wireguard-go на дескрипторе работают в iOS 27 и в системном расширении macOS 26. Запасной путь из таблицы рисков (чтение пакетов через `packetFlow` с передачей в Go) не нужен.
- Базовая память расширения iOS — 5–7 МБ, пик под нагрузкой — 12,2 МБ: запас до цели 35 МБ, которая тогда стояла в требованиях к iOS-версии, большой.

## Влияние на план

- План M2 не меняется: он уже построен на этом пути. Mac владельца прошёл M2-14 2026-11-01.
- M0-11: риск SP-7 в таблице рисков документа платформы iOS (`04-platform-ios-ipados.md`, тег `ios-final`) закрыт.
