### M8-02. Убрать iOS и iPadOS
`macOS` · L · зависит от: M8-01

**Сделать:** тег `ios-final` на последнем коммите с iOS. Убрать:
- таргеты `iOSApp`, `PacketTunnelExtension`, `ControlsExtension`, `iOSIntegrationTests`, `iOSUITests`, платформу iOS в `Package.swift` и iOS-срезы в сборке Go-движка;
- фичи `ServiceCatalog` и `ControlWidgets`, режим «Только выбранные сервисы» во всех слоях и Go-пакет `servicerouting`;
- iOS-ветки в общих фичах;
- скрипты снимков и живых тестов на iPhone, шаги iOS в `check.sh` и `release.sh`;
- строки локализации, которые остались без экрана, документы iOS и вехи M5.

**Тесты сначала:** тесты убранных фич уходят вместе с ними; остальные проходят, поведение на macOS не меняется.
**Готово, когда:** `Scripts/check.sh` проходит, в проекте нет кода и документов, нужных только iOS, а Mac-версия подключается в обоих режимах в тестовой ВМ.

### M8-03. DMG с Developer ID и нотаризацией
`macOS` · M · зависит от: M8-02

**Сделать:** подпись Release сертификатом Developer ID: права Network Extension с суффиксом `-systemextension`, профили Developer ID, требование к клиенту XPC без ветки App Store. `Scripts/release.sh <версия>` архивирует приложение, экспортирует его с подписью Developer ID, нотаризует и сшивает, затем собирает DMG, подписывает и нотаризует его. С флагом `--publish` скрипт создаёт релиз GitHub с DMG и его SHA-256. Данные для нотаризации владелец хранит в связке ключей (`xcrun notarytool store-credentials`), в репозиторий они не попадают.
**Тесты сначала:** требование к клиенту XPC: подпись Developer ID нашей команды проходит, подпись App Store и чужая команда — нет.
**Готово, когда:** DMG из релиза ставится в чистой тестовой ВМ без предупреждений Gatekeeper, расширение одобряется, туннель подключается в обоих режимах.

### M8-05. GitHub Actions и раннер на Mac владельца
`macOS` · M · зависит от: M8-03, M8-04

**Сделать:**
- раннер GitHub Actions на Mac владельца как служба `launchd` с меткой `splitway`;
- workflow проверки (`Scripts/check.sh`) для пушей в `master` и ручного запуска;
- workflow выпуска по тегу `v*` (`Scripts/release.sh --publish`);
- публикация сайта на GitHub Pages облачным раннером;
- настройки репозитория: PR из форков не запускаются на раннере, а их облачные проверки ждут одобрения владельца.

На бесплатном плане GitHub Pages и скачивание релизов без входа работают только у публичных репозиториев, поэтому их проверка завершается в M8-06.
**Тесты сначала:** не требуются (конфигурация); пробный запуск каждого workflow.
**Готово, когда:** пуш в `master` запускает проверку на раннере, тег создаёт релиз с DMG, сайт обновляется сам.

### M8-07. Интеграционные тесты на Mac
`macOS` · M · зависит от: M8-02

**Сделать:** вернуть из тега `ios-final` интеграционные тесты с хост-приложением — `SecretLeakScanTests` и `KeychainTunnelSecretStoreTests` — в таргет `macOSIntegrationTests`, который запускается внутри `Splitway.app` с подписью разработки. Приложение в роли хоста не открывает онбординг и не активирует системное расширение. Шаг в `Scripts/check.sh`, который запускает эти тесты там, где есть сертификат разработки.
**Тесты сначала:** сами тесты; сканер должен находить ключ, если его нарочно записать в файл контейнера.
**Готово, когда:** тесты проходят в `Scripts/check.sh` на Mac владельца и на раннере CI, а `docs/security.md` снова ссылается на работающий сканер.
