# SP-6. UDP и QUIC в transparent proxy

| | |
|---|---|
| Статус | проверен в тестовой ВМ macOS 26.6 (M0-12) 2026-10-31 на сборке `master`; голосовой звонок и 4K-видео — на Mac владельца |
| Вопрос | Работают ли HTTP/3 и звонки через перехват UDP-потоков выбранных приложений (`handleNewUDPFlow`, ретрансляция через `usernet`), без зависаний потоков |
| Код | отдельной ветки нет: проверялась ретрансляция UDP из M4-11 (`UDPFlowRelay`) |
| Вывод | **QUIC на Network.framework работает через прокси**: Safari открывает страницу по HTTP/3, URLSession выбирает HTTP/3 в 9–10 попытках из 10. **QUIC в Chrome через прозрачный прокси не работает**, у выбранного и у невыбранного Chrome: ядро отвечает `ECONNRESET` на `IP_DONTFRAG` и `IP_RECVTOS` перенаправленного сокета, Chrome отказывается от QUIC и молча открывает страницу по HTTP/2. Исправить это в Splitway нельзя |

## Как проверяли

ВМ: macOS 26.6, сборка разработки, туннель коммерческого провайдера (решение D-29), режим «Только выбранные приложения».

- Safari и Chrome по очереди выбраны, открывается `https://cloudflare-quic.com`: страница пишет, каким протоколом её загрузил браузер. Chrome проверен и с `--origin-to-force-quic-on=cloudflare-quic.com:443`: так он идёт только по QUIC и не откатывается на TCP.
- RoutingProbe в режиме `latency` открывает по 10 новых соединений к сайтам Cloudflare с HTTP/3 в записи DNS HTTPS и печатает протокол каждой попытки. Те же замеры — напрямую и в режиме «Весь трафик».
- Сетевой журнал Chrome (`--log-net-log`) и журнал системы для потоков расширения.
- Утилита на C повторяет настройку сокета, как у QUIC в Chrome: `connect`, `SO_RCVBUF`, `SO_SNDBUF`, `IP_DONTFRAG`, `IP_RECVTOS`, `IP_RECVPKTINFO`, `getsockname`, `send`. Через прокси она идёт, когда её запускает выбранный Терминал (решение D-35). Те же шаги — для сокета без `connect` (так работают звонки на WebRTC), сразу и через 0,5 с.

## Результаты

| Клиент | Через прокси | Напрямую | «Весь трафик» |
|---|---|---|---|
| Safari, `cloudflare-quic.com` | HTTP/3 | — | — |
| RoutingProbe, `cloudflare-quic.com` | h3 10 из 10 | h3 10 из 10 | h3 9 из 10, h2 1 |
| RoutingProbe, `www.cloudflare.com` (302 КБ) | h3 9 из 10, h2 1 | — | — |
| RoutingProbe, `blog.cloudflare.com` | h3 9 из 10, h2 1 | — | — |
| RoutingProbe, `one.one.one.one` | h3 3–6, h2 3–6, тайм-аут 1 из 10 | h3 10 из 10 | h2 9 из 10, тайм-аут 1 |
| Chrome, выбран | HTTP/2; с принудительным QUIC — `ERR_CONNECTION_RESET` | — | — |
| Chrome, не выбран, прокси работает | HTTP/2 | — | — |

- `one.one.one.one` (1.1.1.1) плохо отвечает по QUIC и в режиме «Весь трафик», без прокси: это выход провайдера туннеля, а не ретрансляция.
- Сетевой журнал Chrome: UDP-сокет к порту 443 подключается, и в ту же миллисекунду задание QUIC заканчивается ошибкой −101 (`ERR_CONNECTION_RESET`), ни одного байта не отправлено. В журнале системы поток закрывает сам клиент («Closing reads, not closed by plugin») раньше, чем провайдер получает `handleNewUDPFlow`.

Настройка сокета:

| Сокет | Выбранный процесс | Невыбранный процесс | Прокси выключен |
|---|---|---|---|
| с `connect`, сразу | `IP_DONTFRAG` и `IP_RECVTOS` — `ECONNRESET` | `ECONNRESET` | ok |
| с `connect`, через 0,5 с | `ECONNRESET` | ok | ok |
| без `connect`, до первой отправки | ok | ok | ok |
| без `connect`, после первой отправки | `ECONNRESET` | ok | ok |

`SO_RCVBUF`, `SO_SNDBUF`, `getsockname`, `getpeername` и `send` проходят во всех случаях.

## Вывод

- Ретрансляция UDP справляется с QUIC: HTTP/3 Safari и URLSession идёт через туннель, ответы по 300 КБ приходят без зависаний.
- Перенаправленный в прозрачный прокси UDP-сокет не принимает опции уровня IP. Пока провайдер решает судьбу потока, это касается любого сокета с `connect`, а у выбранного приложения — всё время. Chrome задаёт `IP_DONTFRAG` сразу после `connect`, поэтому QUIC в Chrome не работает при включённом режиме «Только выбранные приложения», даже если Chrome не выбран. Страницы открываются по HTTP/2.
- Звонки на WebRTC задают опции сокета до первой отправки, у них опции проходят. Работает ли звонок через перехват, покажет проверка на Mac владельца.

## Влияние на план

- M4-10: HTTP/3 выбранного Chrome идёт по TCP. Загрузка 1 ГБ и 4K-видео в Chrome проверяют TCP-ретрансляцию, а не QUIC.
- TransparentProxy: ограничение записано в документе фичи.
- Не проверено: голосовой звонок (Telegram или WhatsApp) и 4K-видео — на Mac владельца.
