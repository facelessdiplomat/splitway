## Назначение

Общие компоненты интерфейса всех фич:
- бейдж статуса;
- строки «ключ–значение» и идентификатора;
- пустое состояние и кнопка с загрузкой;
- документ для сохранения файлов;
- цвет вспомогательного текста;
- контейнер, который прокручивается, только когда содержимому не хватает места.

Компоненты рассчитаны на VoiceOver и все размеры Dynamic Type.

## Принцип работы

- `StatusBadge` показывает статус значком и текстом в капсуле цвета `StatusTone`; VoiceOver читает его одним элементом.
- `KeyValueRow` — `LabeledContent` с ключом и значением цвета `supportingText`. VoiceOver читает строку одним элементом («Версия, 0.1.0»), а не голым значением.
- `IdentifierRow` показывает длинный идентификатор (ключ) моноширинным шрифтом в одну строку с уменьшением. На крупных размерах шрифта доступности он переносится на несколько строк без уменьшения.
- `EmptyStateView` — значок, заголовок (для VoiceOver — заголовок), сообщение и действия. Текст растёт до самых крупных размеров, а если не помещается, экран прокручивается.
- `OverflowScrollView` показывает содержимое как есть, а если оно не помещается по высоте — внутри `ScrollView` (`ViewThatFits`). Им пользуются пустые состояния и онбординг.
- `LoadingButton` — кнопка, которая на время действия показывает индикатор.
- `ExportedDataDocument` — `FileDocument` с готовыми данными для `fileExporter`: экспорт туннелей и журнала.
- `View.plainTextInput()` — ввод без автоисправлений: ключи, адреса, домены. Им пользуется редактор туннеля.
- `ShapeStyle.supportingText` — цвет вспомогательного текста вместо `.secondary`. Контраст не ниже 4,5:1 и на светлом, и на тёмном фоне: светлая тема `#6C6C70`, тёмная `#AEAEB2`. Для режима «Повышенный контраст» есть более тёмный и более светлый варианты.

**Доступность приложения** (M3-14):

- Акцент приложения — `AccentColor` в `Apps/Shared/Assets.xcassets`:
  - светлая тема — `#0055C4`: контраст с белым 6,8:1 и для синего текста, и для белого текста на синих кнопках;
  - тёмная тема — системный `#0A84FF`;
  - есть варианты повышенного контраста.
- Заголовки разделов форм окрашены в `supportingText`.
- Поля редактора подписаны для VoiceOver своим названием. На крупных размерах шрифта название встаёт над полем. Строка туннеля читается одной фразой («Office, Весь трафик, Отключён») и отдельным переключателем; на крупных размерах переключатель уходит под текст.
- Команды меню приложения — `TunnelLibraryCommands`. Список сочетаний — в [TunnelLibrary](TunnelLibrary.md).
- Клавиатура в листах (M6-05): кнопка, которая закрывает или отменяет лист («Закрыть», «Отмена», «Позже», «Готово»), отвечает на Esc (`.keyboardShortcut(.cancelAction)`). ⏎ подтверждает импорт, ⌘S сохраняет в редакторе туннеля.

## Публичный API

`StatusBadge`, `StatusTone`, `KeyValueRow`, `IdentifierRow`, `EmptyStateView`, `OverflowScrollView`, `LoadingButton`, `ExportedDataDocument`, `ShapeStyle.supportingText`, `View.plainTextInput()`.

## Решения

- Только системные шрифты и SF Symbols. Цвета системные, кроме `supportingText` и акцента приложения: их контраст проверен.
- Компоненты без логики не покрываются unit-тестами (правило 4), у каждого есть превью в Xcode.
- Кнопка закрытия листа получает `.keyboardShortcut(.cancelAction)` явно: на macOS размещение `.cancellationAction` само Esc не назначает, и журнал в тестовой ВМ по Esc не закрывался.

## Спорные решения

| Решение | Альтернативы | Почему так | Когда пересмотреть |
|---|---|---|---|
| Своё `EmptyStateView` вместо `ContentUnavailableView` | Системный компонент | `ContentUnavailableView` не даёт тексту расти до крупных размеров доступности и обрезает его; аудит доступности это ловил | Если системный компонент начнёт поддерживать все размеры |
| `supportingText` вместо `.secondary` | `.secondary` | `.secondary` на светлом фоне даёт 3,5:1, ниже 4,5:1 для обычного текста | Если системный цвет станет контрастнее |
| Тёмный акцент в светлой теме | Системный синий | Системный синий с белым даёт 4:1 | Нет |

## Отступления от правил разработки

Нет.

## Ограничения и известные проблемы

- В тёмной теме белый текст на синих кнопках даёт 3,6:1, как у системного синего; режим «Повышенный контраст» даёт более контрастный вариант.
- Автоматического аудита доступности сейчас нет: UI-тесты с `performAccessibilityAudit` работали на симуляторах iPhone и iPad и убраны вместе с iOS (M8-02), а UI-тестам macOS нужно место, где их гонять ([отложенные проверки](../05-tasks/deferred-checks.md)).
- VoiceOver на Mac проверяется вручную ([отложенные проверки](../05-tasks/deferred-checks.md)).

## Тесты

Unit-тестов нет: компоненты без логики (правило 4). UI-тестов с аудитом доступности после M8-02 нет (раздел «Ограничения»).
