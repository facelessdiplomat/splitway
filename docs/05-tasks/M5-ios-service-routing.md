## ServiceCatalog

### M5-01. Содержимое каталога
`iOS+iPadOS` · M · зависит от: M0-11

**Сделать:** `Resources/ServiceCatalog/catalog.json` для стартового набора из 15 сервисов (решение D-15). Для каждого сервиса: суффиксы доменов и подсети из опубликованных источников (например, CIDR-список Telegram); источник указан в поле `notes`. Иконки нейтральные (монограмма или SF Symbol и цвет), без логотипов брендов, чтобы не нарушать чужие товарные знаки (решение D-16). Тест каталога запускается в `Scripts/check.sh`.
**Тесты сначала:** тест каталога: схема валидна, все домены и подсети разбираются доменными типами, `id` уникальны, у каждой записи есть хотя бы одно правило.
**Готово, когда:** каталог проходит тест, каждый сервис вручную проверен на устройстве через SP-4-прототип или M5-07.

### M5-02. Домен каталога и своих правил
`iOS+iPadOS` · M · зависит от: M1-10, M5-01

**Сделать:** `ServiceProfile`, `ServiceRule` (суффикс домена или подсеть), `CustomService` (пользовательский сервис), `DomainSuffixSet` (суффиксное дерево: поиск, минимизация вложенных суффиксов), сценарии `LoadServiceCatalogUseCase`, `SaveCustomServiceUseCase`, `UpdateServiceSelectionUseCase`; адаптер `BundledServiceCatalogRepository`.
**Тесты сначала:** минимизация (`t.me` поглощает `a.t.me`); свой сервис с невалидным доменом отклоняется; выбор сохраняется в `RoutingPolicy`.
**Готово, когда:** сценарии покрыты тестами на фейках.

### M5-03. Компилятор плана маршрутизации
`iOS+iPadOS` · L · зависит от: M5-02, M1-09

**Сделать:** `ServiceRoutingPlanCompiler`: выбор + каталог + конфиг туннеля → `ServiceRoutingPlan`: маршруты (подсети ∩ `AllowedIPs`), домены для `matchDomains` (минимизированные), служебная подсеть и виртуальный DNS (с запасным диапазоном при конфликте с адресами конфига), DNS для пересылки (из конфига или настройки по умолчанию), наличие IPv6. Список предупреждений: подсеть вне `AllowedIPs`, пустой выбор, конфликт диапазонов.
**Тесты сначала:** табличные тесты на каждое правило и предупреждение; детерминированность (одинаковый вход → одинаковый план, порядок стабилен).
**Готово, когда:** план полностью определяется входом и сериализуется в JSON для Go.

## Go: servicerouting

### M5-04. Пакеты, контрольные суммы, трансляция адресов
`iOS+iPadOS` · L · зависит от: M2-03, SP-4

**Сделать:** разбор заголовков IPv4/IPv6/TCP/UDP без аллокаций; инкрементальный пересчёт контрольных сумм (RFC 1624); `AddressTranslator`: таблица соединений по 5-tuple, DNAT для исходящих к фиктивным адресам, SNAT для ответов, таймауты по протоколу, ограничение размера таблицы.
**Тесты сначала:** golden-тесты на сгенерированных пакетах (контрольная сумма после трансляции совпадает с полным пересчётом); fuzz-тесты разборщика (`go test -fuzz`); вытеснение при переполнении таблицы. Бенчмарк трансляции на пакет.
**Готово, когда:** трансляция не выделяет память на пакет и проходит fuzz без паник.

### M5-05. Пул фиктивных адресов, перехват DNS, обёртка устройства
`iOS+iPadOS` · L · зависит от: M5-04

**Сделать:** `FakeAddressPool` (выдача по домену, TTL, LRU, удержание при активных соединениях); `DNSInterceptor` (`golang.org/x/net/dns/dnsmessage`): запрос к виртуальному DNS → пересылка в туннель → переписывание A/AAAA с учётом CNAME-цепочек, TTL ≤ 60 с, пустой AAAA при отсутствии IPv6; `TranslatingDevice` — обёртка над `tun.Device` с поддержкой пакетных `Read`/`Write` wireguard-go.
**Тесты сначала:** DNS-ответ с CNAME-цепочкой; AAAA без IPv6; повторный запрос того же домена возвращает тот же адрес; освобождение адреса без соединений; сквозной тест «DNS-запрос → ответ с фиктивным адресом → TCP SYN → DNAT» на `tuntest`.
**Готово, когда:** сквозной Go-тест проходит, таблицы ограничены по памяти.

### M5-06. Мост и адаптер плана
`iOS+iPadOS` · M · зависит от: M5-03, M5-05

**Сделать:** `tc_fd_tunnel_set_service_routing(handle, plan_json)` (при старте и при изменении); DTO плана в Swift (`Codable`) и в Go; Swift-метод адаптера `applyServiceRoutingPlan`.
**Тесты сначала:** контрактный тест: JSON из Swift-тестов разбирается Go-тестом (общая фикстура в репозитории); неизвестная версия DTO → ошибка.
**Готово, когда:** Swift и Go используют одну фикстуру контракта.

### M5-07. Интеграция в пакетный туннель
`iOS+iPadOS` · M · зависит от: M2-06, M5-06

**Сделать:** в режиме `.selectedServices` `TunnelNetworkPlan` строится из `ServiceRoutingPlan`: маршруты без маршрута по умолчанию, `dnsSettings` с виртуальным DNS и `matchDomains`. Сессия применяет план к Go-движку. Изменение выбора: новый план → `setTunnelNetworkSettings` (только если изменились маршруты или домены) + обновление Go.
**Тесты сначала:** построение `TunnelNetworkPlan` из `ServiceRoutingPlan`; сессия вызывает `setTunnelNetworkSettings` только при изменении маршрутов или доменов.
**Готово, когда:** выбранный сервис работает через туннель, остальные — напрямую, на iPhone и iPad.

### M5-08. Экраны выбора сервисов
`iOS+iPadOS` · M · зависит от: M3-08, M5-02

**Сделать:** список сервисов с поиском и категориями; экран сервиса (правила, ограничения); редактор своего сервиса (домены и подсети с валидацией на лету); сводка в деталях туннеля; экран «Как это работает и ограничения» (раздел 4.5 документа iOS).
**Тесты сначала:** `ServicePickerModel` (поиск, выбор, предупреждения компилятора отображаются), `CustomServiceEditorModel` (валидация, сохранение).
**Готово, когда:** пользователь выбирает сервисы и создаёт свой без чтения документации.

### M5-09. Память и производительность на устройстве
`iOS+iPadOS` · M · зависит от: M5-07

**Сделать:** Instruments (Allocations, VM Tracker, Time Profiler) для расширения под нагрузкой: 4K-видео через выбранный сервис + обычный трафик мимо туннеля; настройка лимита памяти Go и размеров таблиц.
**Тесты сначала:** не требуются (измерения); результаты в документе фичи.
**Готово, когда:** пик памяти ≤ 35 МБ, нет роста памяти за час работы.

### M5-10. Проверка корректности и утечек на устройстве
`iOS+iPadOS` · M · зависит от: M5-07

**Сделать:** чек-лист: внешний IP внутри выбранного сервиса = IP сервера; в невыбранном браузере — IP провайдера; DNS-запросы выбранных доменов идут через туннель (проверка DNS-сервисами, которые возвращают адрес спросившего резолвера); поведение после выключения VPN; сотовая сеть IPv6-only с NAT64; смена Wi-Fi ↔ сотовая.
**Тесты сначала:** не требуются (ручная проверка).
**Готово, когда:** все пункты пройдены на iPhone и iPad.
