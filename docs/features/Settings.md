## Назначение

Экран настроек приложения. Сейчас он показывает версию и сборку приложения и лицензии открытого ПО, которое входит в приложение. Тест следит, чтобы у каждой зависимости проекта была запись в списке лицензий.

## Зависимости

| Тип | Что | Зачем |
|---|---|---|
| Фичи проекта | `SharedKernel`; в `Presentation` — `DesignSystemPresentation` | общее ядро; строка «ключ–значение» и пустое состояние |
| Системные фреймворки | Foundation, Dispatch; в `Presentation` — SwiftUI, Observation | ресурсы пакета и JSON; очередь чтения; экран настроек |
| Сторонние библиотеки | нет | |

## Принцип работы

**Лицензии.**

- `ThirdPartyNotice` — запись о стороннем компоненте:
  - название (`Go`, `wireguard-go`);
  - идентификатор лицензии SPDX;
  - зависимости проекта, которые она покрывает (идентичности пакетов SwiftPM и модули Go);
  - текст лицензии с копирайтом.
- `paragraphs` собирает текст в абзацы: строки абзаца склеиваются, пункт списка (`*`, `-`, `•`) начинает новый абзац. Жёсткие переносы исходного файла не ломают текст на узком экране.
- Записи лежат в ресурсах `SettingsInfrastructure` (`Resources/ThirdPartyNotices`):
  - манифест `ThirdPartyNotices.json` — название, лицензия, зависимости и имя файла текста;
  - тексты лицензий `.txt`, взятые из самих зависимостей.
- `BundledThirdPartyNoticeSource` читает их на своей очереди, а не на главном потоке или кооперативном пуле. `LoadThirdPartyNoticesUseCase` сортирует записи по названию без учёта регистра.
- Состав сейчас:
  - Go: стандартная библиотека и рантайм, `golang.org/x/crypto`, `golang.org/x/net`, `golang.org/x/sys`; BSD-3-Clause;
  - wireguard-go (MIT);
  - ZIPFoundation (MIT);
  - WireGuardKit (MIT): поиск дескриптора `utun` в `UtunDescriptorLocator` повторяет подход `WireGuardAdapter` из WireGuardKit.

**Экран.**

- `SettingsScreen` — форма в `NavigationStack`: раздел «О приложении» (версия и сборка из `AppVersion`) и переход к «Лицензиям открытого ПО».
- `ThirdPartyNoticesModel` загружает список при открытии и хранит состояние `ThirdPartyNoticesState`: загрузка, список или «Лицензии недоступны». Текст лицензии открывается отдельным экраном, его можно выделить.
- На iOS и iPadOS настройки открываются листом (`View.settingsSheet(_:)`, `SettingsPresenter.show()`) из пункта «Настройки» меню «⋯» списка туннелей. На macOS это сцена `Settings` приложения: пункт «Настройки…» меню приложения и ⌘,.

## Публичный API

`ThirdPartyNotice` (с `paragraphs`), `AppVersion`, `ThirdPartyNoticeSource`, `ThirdPartyNoticeError`, `LoadThirdPartyNoticesUseCase`; адаптеры `BundledThirdPartyNoticeSource`, `SettingsAssembly`; экран — `SettingsScreen`, `SettingsPresenter`, `ThirdPartyNoticesModel`, `ThirdPartyNoticesState`, модификатор `settingsSheet(_:)`.

## Решения

- Список лицензий — данные (манифест и тексты), а не код: добавить запись можно без изменения Swift, а тест проверяет данные такими, какими они попадут в приложение.
- Тексты лицензий копируются из самих зависимостей: из кэша модулей Go, установки Go и исходников ZIPFoundation. У wireguard-go в файле лицензии нет строки копирайта, поэтому она взята из заголовков его исходников. Текст WireGuardKit взят из файла `COPYING` репозитория wireguard-apple.
- Одна запись «Go» покрывает стандартную библиотеку и модули `golang.org/x`: у них один и тот же текст лицензии.
- Тест ищет зависимости в `Packages/SplitwayKit/Package.resolved`, `Packages/TunnelCore/Package.resolved`, `Packages/TunnelCore/go/go.mod` (включая директиву `go`, то есть стандартную библиотеку) и в удалённых пакетах `project.yml`. Утилиты из `Scripts` в приложение не попадают и не проверяются.
- Зависимости, которых нет в собранном приложении, перечислены в тесте явно: `go.uber.org/goleak` нужен только тестам, а `golang.zx2c4.com/wintun` — только Windows.

## Спорные решения

| Решение | Альтернативы | Почему так | Когда пересмотреть |
|---|---|---|---|
| Записи gVisor и Sparkle появятся вместе с этими зависимостями | Добавить их заранее, как перечислено в плане M3-13 | Экран показывает только то, что реально входит в приложение; тест упадёт, как только gVisor (M4) или Sparkle (M7) появятся в манифестах без записи | Нет |
| Тест падает и на «лишней» записи, которая больше не покрывает ни одной зависимости | Проверять только отсутствие записей | Удалённая зависимость не должна оставаться на экране лицензий | Нет |
| Тексты показываются абзацами, а не как в файле | Моноширинный текст с исходными переносами | На iPhone исходные переносы ломали строки посередине | Если лицензия с таблицей или отступами окажется нечитаемой |
| Версия и сборка, без копирайта приложения | Строка копирайта в «О приложении» | На macOS копирайт показывает стандартное окно «О программе» (`NSHumanReadableCopyright`) | Если копирайт понадобится и на iOS |

## Ограничения и известные проблемы

- Окно настроек macOS собирается, но запуск ждёт подписи (M0-04). Экран проверен в симуляторе iPhone на русском языке.
- Настройки приложения (запуск при входе, иконка в Dock) — M6.
- Строки манифеста, которые не удаётся прочитать, делают недоступным весь список: частичный список лицензий хуже, чем явное сообщение.

## Тесты

- 5 тестов в `SettingsTests`: сортировка по названию без учёта регистра, недоступный источник, сборка абзацев (склейка строк, пункты списка, пустые строки).
- 4 теста в `SettingsInfrastructureTests`:
  - разбор манифестов находит известные зависимости, иначе проверка покрытия ничего бы не значила;
  - у каждой зависимости из приложения есть запись;
  - нет записей о зависимостях, которых больше нет;
  - у каждой записи есть лицензия и строка копирайта.
  Тест покрытия проверен на сломанном манифесте: он падает, если убрать запись ZIPFoundation или добавить запись о несуществующей зависимости.
- 2 теста в `SettingsPresentationTests`: список по названию после загрузки, недоступные лицензии.

Запуск: `swift test --package-path Packages/SplitwayKit --filter Settings`.
