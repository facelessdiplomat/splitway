# SP-8. Запуск VPN из контрола без открытия приложения

| | |
|---|---|
| Статус | проверен в симуляторе iPhone 18 Pro (iOS 27.2) и на iPhone 13 Pro (iOS 27.2) 2026-11-01: intent контрола выполняется в расширении виджетов и подключает и отключает туннель без открытия приложения. Экран блокировки проверяет владелец (M6-04) |
| Вопрос | В каком процессе выполняется `perform()` интента контрола и можно ли оттуда управлять VPN-конфигурацией без открытия приложения ([04-platform-ios-ipados.md](../../04-platform-ios-ipados.md), разделы 8 и 10) |
| Код | ветка `spike/SP-8`, в `master` не сливается; рабочий код — фича [ControlWidgets](../ControlWidgets.md) |
| Вывод | **Intent выполняется в процессе расширения виджетов, а не в приложении**, даже когда его тип собран и в приложение. Расширение само загружает VPN-конфигурацию, записывает в неё туннель и запускает его. Записать туннель можно, только изменив поля загруженного объекта протокола: новый `NETunnelProviderProtocol`, созданный в расширении, система отклоняет. Открывать приложение (`openAppWhenRun`) не нужно |

## Как проверяли

- Ветка `spike/SP-8`: widget extension `ControlsExtension` с `ControlWidgetToggle`. Его `SetValueIntent` собран и в приложение, и в расширение.
- `perform()` и `currentValue()` пишут в файл App Group имя процесса, bundle ID и ответ `NETunnelProviderManager.loadAllFromPreferences()`.
- Расширение получило entitlement Network Extension (`packet-tunnel-provider`), App Group и группу Keychain, как пакетный туннель. Такой же набор у VPN-клиента NetBird, который подключает туннель из своего контрола ([netbirdio/ios-client](https://github.com/netbirdio/ios-client), `NetBirdWidgetExtension`).
- Симулятор iPhone 18 Pro, iOS 27.2:
  - контрол добавлен в Пункт управления и нажат;
  - Пункт управления закрыт и открыт снова.
- iPhone 13 Pro, iOS 27.2, сборка фичи M6-04:
  - живой UI-тест `LiveControlCenterTests` открывает Пункт управления, нажимает контрол «Туннель Splitway» и сверяет состояние туннеля с приложением;
  - действия контрола и временная диагностика NetworkExtension пишут в журнал Splitway, журнал забирается с телефона через `devicectl`.

## Результаты

| Проверка | Результат |
|---|---|
| Процесс `perform()` | `ControlsExtension` (`com.facelessdiplomat.splitway.controls`), хотя intent собран в оба таргета; на iPhone записи действия приходят из расширения |
| Процесс `currentValue()` | `ControlsExtension` |
| `NETunnelProviderManager` в симуляторе | `NEVPNErrorDomain` 5 «IPC failed»: VPN в симуляторе недоступен |
| Загрузка конфигурации в расширении на iPhone | видна конфигурация Splitway: одна, включена, с туннелем в `providerConfiguration` |
| Запуск и остановка установленного туннеля из расширения | работают: `startVPNTunnel()` и `stopVPNTunnel()`, туннель стартует через 0,4 с после нажатия |
| Запись нового `NETunnelProviderProtocol` из расширения | отклонена: `NEVPNErrorDomain` 1 «configuration type is wrong» |
| Изменение полей загруженного протокола из расширения | сохраняется: адрес сервера изменён и возвращён, затем туннель записан и запущен |
| После `perform()` | система сама перечитывает значение контрола |
| Повторное открытие Пункта управления | `currentValue()` не вызывается: система показывает сохранённое значение |
| Галерея контролов | в симуляторе после первой установки контрола в галерее не было, хотя `chronod` его проиндексировал. После перезагрузки симулятора он появился, а следующие установки перезагрузки не требовали. На iPhone контрол появился в галерее сразу |
| Системный переключатель VPN | в блоке «Связь» Пункта управления у iOS свой переключатель VPN. Он включает ту же конфигурацию Splitway, но не выбирает туннель и не проходит через расширение: первая проверка владельца прошла через него, поэтому контрол проверен живым тестом |
| Экран блокировки | проверяет владелец (M6-04) |

## Вывод

- Intent контрола выполняется в расширении. Приложение не запускается, поэтому расширение само читает библиотеку туннелей, записывает туннель в слот VPN и запускает его.
- Расширению нужны Network Extension, App Group и группа Keychain: без Keychain не прочитать конфигурацию туннеля, которого ещё нет в слоте.
- Записывать туннель в слот нужно, меняя поля загруженного объекта протокола. Новый объект `NETunnelProviderProtocol`, созданный в расширении, система считает конфигурацией другого типа. Видимо, тип берётся из bundle ID процесса, который создал объект.
- Создать первую VPN-конфигурацию расширение не пытается: для этого нужно разрешение пользователя, а из Пункта управления его не запросить.
- Значение контрола система хранит у себя. Когда статус туннеля меняется не через контрол, обновление нужно запросить явно: `ControlCenter.shared.reloadControls(ofKind:)`.
