# Тестовый туннель

Для разработки и тестов используется готовый конфиг WireGuard коммерческого провайдера, а не свой сервер (решение D-29 в [журнале решений](../../docs/00-decisions.md)).

## Где хранится конфиг

- Только вне репозитория, например в iCloud Drive. `Scripts/lint.sh` и хук `pre-commit` отклоняют изменения, если в репозитории появляется ключ WireGuard или `.conf`-файл вне каталогов `Fixtures`.
- Скрипты, тесты утечек и спайки получают путь из переменной окружения:

  ```bash
  export SPLITWAY_TEST_TUNNEL_CONFIG="$HOME/Library/Mobile Documents/com~apple~CloudDocs/VPN/<имя>.conf"
  ```

- Код читает конфиг во время выполнения и никогда не встраивает ключ в исходники — даже в ветках `spike/*`: всё, что однажды закоммичено, остаётся в истории git.
- Фикстуры парсера в `Tests/**/Fixtures` используют только сгенерированные тестовые ключи.

## Ограничения провайдерского конфига

- **Одна пара ключей — одно устройство в каждый момент времени.** Если подключить один конфиг одновременно на Mac и на iPhone, сервер отвечает тому устройству, которое прислало пакет последним. Для параллельных тестов нужен второй конфиг с новым ключом из кабинета провайдера.
- **Журналы сервера недоступны.** Куда ушёл DNS-запрос, проверяем сервисами, которые возвращают адрес спросившего резолвера:

  ```bash
  dig +short TXT o-o.myaddr.l.google.com
  dig +short whoami.akamai.net
  ```

- **Только IPv4.** В конфиге `AllowedIPs = 0.0.0.0/0` без `::/0` и без IPv6-адреса. В режиме «Весь трафик» IPv6 без отдельной блокировки идёт мимо туннеля (решение D-30 принимается до задачи M2-05).
- **Внешний IP через туннель отличается от IP провайдера интернета.** На этом построены тесты утечек (M4-17, M5-10, M7-05).
