# Проверки на Mac владельца

По решению D-36 всё, что умеет тестовая ВМ, проверяется в ней, а владелец на своём Mac подтверждает остальное. Раньше выводы спайков и замеры подтверждались на настоящем Mac (решение D-32): тестовая ВМ работает через NAT хоста, с 4 vCPU и macOS 26, а на Mac — macOS 27, своя сеть, сон и смена сетей. Здесь собраны все проверки, которые ждут Mac, с командами и ожидаемым результатом. Всё вместе — около двух часов, части независимы, их можно проходить в разные дни. Проверки пройдены в ВМ 2026-10-31 и на Mac владельца 2026-11-01. Осталось сравнить на Mac отправку (M4-16), раздел «Осталось на Mac владельца».

После частей 3–7 закрывается M0-11, точка решения по спайкам, и за ней начинается iOS-часть M5.

## Итоги проверки в ВМ 2026-10-31

По решению D-36 всё, что умеет тестовая ВМ, проверено в ней (macOS 26.6, сборка `master`). Чего ВМ проверить не может, владелец проверил на своём Mac — следующий раздел.

| Часть | В ВМ |
|---|---|
| 1 | Пройдена: адрес, DNS, статистика, смена сети, отключение снаружи (через 1 с «Отключён»), неверный ключ. Чужой ключ пира: «Ещё не было» рукопожатия, статус при этом «Подключён», «Получено» — ноль, трафик мимо туннеля не уходит |
| 2 | Пройдена: подключение, переключение и отключение из меню, галочка, строка состояния и режим, «Открыть Splitway», «Настройки…», вопрос при выходе. С открытым листом (онбординг, импорт) AppKit не завершает приложение — стандартное поведение |
| 3 | Пройдена: `selected` и `background` — PASS, `unavailable` — PASS после исправления скрипта (общий кэш `mDNSResponder`, [DNSProxy](../features/DNSProxy.md)); выбор приложений сохраняется после ⌘Q |
| 4 | Пройдена: Safari, Chrome, Telegram, VS Code, Терминал и запущенный им `curl` (D-35) идут через туннель, невыбранные — напрямую; при недоступном туннеле выбранный Chrome блокируется, Safari работает. Firefox не перепроверялся: первый запуск требует принять Terms of Use ([SP-2](../features/spikes/SP-2.md)) |
| 5 | HTTP/3 Safari и URLSession через прокси работает; QUIC в Chrome при включённом прокси не работает, страницы идут по HTTP/2 ([SP-6](../features/spikes/SP-6.md)) |
| 6 | Загрузка — цели M4-16 выполнены, 1 ГБ через прокси — 203 Мбит/с; отправку в ВМ не сравнить: путь из ВМ теряет пакеты в обоих режимах (разбор 2026-11-01) ([TransparentProxy](../features/TransparentProxy.md), «Производительность») |
| 7 | Пройдена: после перезагрузки туннель включается без приложения, ключа нет ни в настройках VPN, ни открытым текстом в System Keychain (SIP в ВМ выключен) |
| 8 | Выделения решения по потоку — в Instruments на хосте, на горячем пути их нет (M4-01). Time Profiler расширения в ВМ не записывается |

Попутные находки:

- Несколько файлов `.conf`, открытых в Finder разом, дают предпросмотр только первого: SwiftUI вызывает `onOpenURL` только для него. Модель собирает файлы в один предпросмотр (ветка `fix/import-every-opened-file`), осталось брать адреса из делегата приложения.
- Смена режима «Только выбранные приложения» → «Весь трафик» → обратно сбрасывала выбор приложений: политика хранила только выбор активного режима. Исправлено по решению D-37 2026-11-01: политика помнит выбор каждого режима. Проверено в ВМ на туннеле без сервера: Safari выбран, туннель сохранён с «Весь трафик», при возврате режима редактор показывает «1 app selected» и отмеченный Safari, в том числе после перезапуска приложения.
- Туннель без рукопожатия показывался «Подключённым» в обоих режимах, без предупреждения, что сервер не отвечает. По решению D-38 2026-11-01 детали туннеля показывают «Сервер не отвечает», если ни один пир не ответил на три попытки рукопожатия. Проверено в ВМ на туннеле с недоступным сервером, который ведёт только 10.99.0.0/16: без трафика за 36 с предупреждения нет (отправлено 0 байт); после пинга в эту сеть на второй попытке (296 байт) его ещё нет, на третьей (444 байта) оно появляется, а после отключения пропадает.

## Осталось на Mac владельца

1. **Отправка (M4-16).** В ВМ её не сравнить: путь из ВМ теряет пакеты в обоих режимах, разброс 3–226 Мбит/с ([TransparentProxy](../features/TransparentProxy.md), «Разбор отправки 2026-11-01»). Нужен RoutingProbe из части 0. Режимы чередуются, в каждом по три отправки: «Весь трафик», затем «Выбранные приложения» с RoutingProbe, затем ещё раз оба. Команда: `/Applications/RoutingProbe.app/Contents/MacOS/RoutingProbe upload https://speed.cloudflare.com/__up 3`. Цель — медиана через прокси не меньше 90 % от «Весь трафик». Прислать четыре строки `upload median`.

## 0. Подготовка

1. Обновить рабочую копию: `git pull`.
2. Собрать и поставить приложение: `Scripts/install-mac-app.sh`. Скрипт собирает подписанную сборку разработки с новым номером сборки, закрывает запущенный Splitway и кладёт новый в `/Applications`.
3. Запустить Splitway. Включить расширение: «Системные настройки › Основные › Объекты входа и расширения › Сетевые расширения», затем разрешить добавление конфигурации VPN, когда система спросит.
4. Импортировать тестовый туннель `cz-prg.conf` (решение D-29): «Импорт из файла» или перетащить файл в окно.
5. Собрать RoutingProbe: `Scripts/build-routing-probe.sh && cp -R build/RoutingProbe/RoutingProbe.app /Applications/`.
6. Поставить, если их нет: Chrome, Firefox, Telegram, Slack или Discord.

Адреса во всех проверках только сравниваются: присылать их не нужно, достаточно «отличается» или «совпадает».

## 1. «Весь трафик» (M2-14)

Туннель cz-prg в режиме «Весь трафик».

| Проверка | Как | Ожидается |
|---|---|---|
| Рукопожатие и внешний адрес | подключить; в Терминале `curl -s https://api.ipify.org` до и после подключения | в деталях «Последнее рукопожатие» — меньше двух минут назад; адрес после подключения отличается |
| DNS через туннель | `dig +short whoami.akamai.net` до и после подключения | адрес резолвера отличается |
| Статистика | открыть детали туннеля и что-нибудь загрузить | «Получено» и «Отправлено» растут |
| Смена сети | Wi-Fi → Ethernet (или другой Wi-Fi, или точка доступа iPhone) и обратно | туннель остаётся подключённым, через 10–20 с `curl` снова отвечает адресом туннеля |
| Сон | усыпить Mac на 2–3 минуты и разбудить | туннель работает без переподключения вручную |
| Отключение снаружи | «Системные настройки › VPN» → выключить Splitway | приложение показывает «Отключён» |
| Чужой ключ | «Дублировать» cz-prg, в копии изменить одну букву в середине открытого ключа пира, подключить | рукопожатия нет («Ещё не было»); записать, что ещё показывает приложение |
| Неверный ключ | в копии вставить ключ неправильной длины и сохранить | понятная ошибка, сохранить не даёт |

## 2. Строка меню (M6-01)

Закрыть окно Splitway, всё делать из значка в строке меню.

- Значок меняется: щит, щит с половинной заливкой при подключении, щит с галочкой — подключено, щит с восклицательным знаком — ошибка.
- Выбор туннеля в меню подключает его, рядом появляется галочка. Выбор другого переключает на него. Повторный выбор активного — отключает.
- Наверху строка «cz-prg: Подключён» и режим маршрутизации.
- «Открыть Splitway» открывает окно, «Настройки…» — настройки.
- «Завершить Splitway» с подключённым туннелем спрашивает «Отключить «cz-prg» перед выходом?»: «Отменить» оставляет приложение, «Отключить и выйти» отключает туннель и закрывает приложение. Без активного туннеля приложение закрывается сразу.

## 3. Утечки в режиме выбранных приложений (M4-17, M4-04, SP-9)

Подробности — в [README RoutingProbe](../../Scripts/RoutingProbe/README.md).

1. Туннель cz-prg, режим «Выбранные приложения», в выборе только RoutingProbe. Подключить.
2. `Scripts/leak-test-macos.sh selected` — ожидаются только PASS; проверка IPv6 может быть SKIP, если в сети нет IPv6. Здесь же подтверждается SP-9: DNS выбранного RoutingProbe отвечает резолвер туннеля, а `dig` — системный (решение D-34).
3. «Дублировать» cz-prg, в копии endpoint `192.0.2.1:51820`, в выборе RoutingProbe, включить «Блокировать, если туннель недоступен». Подключить и подождать 20 с.
4. `Scripts/leak-test-macos.sh unavailable` — ожидаются только PASS.
5. `Scripts/leak-test-macos.sh background` — строка INFO показывает, куда ушла фоновая загрузка. Ожидается «напрямую» (ограничение M4-19).
6. M4-04: закрыть Splitway совсем (⌘Q) и открыть снова — выбор приложений на месте. Пометка «не поддерживается» в листе выбора понадобится, только если в части 4 какое-то приложение не заработает.

## 4. Какие приложения видит прокси (SP-2, M4-09)

Режим «Выбранные приложения», в выборе по одному приложению за раз. Невыбранный `curl` в Терминале показывает прямой адрес.

| Приложение | Как | Ожидается |
|---|---|---|
| Safari, Chrome, Firefox | выбрать браузер, открыть в нём `https://api.ipify.org` | адрес отличается от `curl`; невыбранный браузер в это время показывает прямой адрес |
| Slack или Discord (Electron), Telegram | выбрать приложение и пользоваться им | приложение работает; в деталях туннеля «Получено» растёт, пока им пользуешься |
| Claude (решение D-35) | выбрать Claude и перезапустить его; во вкладке Code попросить выполнить `curl -s https://api.ipify.org` | и сам Claude, и Claude Code, и `curl`, который он запустил, идут через туннель: адрес отличается от `curl` в Терминале |
| Те же приложения при недоступном туннеле | туннель из части 3 (`192.0.2.1`), блокировка включена, выбрано приложение | выбранное приложение не может подключиться, Safari при этом работает: значит, его трафик действительно идёт через прокси |

Если какое-то приложение ведёт себя иначе — записать какое и что видно.

## 5. UDP, QUIC и звонок (SP-6)

Режим «Выбранные приложения».

- Выбрать Chrome, открыть `https://cloudflare-quic.com`: страница открывается и пишет, что используется HTTP/3.
- В Chrome включить на YouTube видео 4K на 2–3 минуты (YouTube отдаёт его по QUIC): без зависаний.
- Выбрать Telegram (или WhatsApp) и позвонить на 1–2 минуты: звук в обе стороны, связь не рвётся.

## 6. Скорость (SP-3, M4-16, M4-05, M4-10)

Скорость пути меняется от прогона к прогону, поэтому режимы чередуются. Каждый прогон — 3–4 минуты.

1. «Весь трафик»: `Scripts/relay-benchmark-macos.sh full-1`
2. «Выбранные приложения» с RoutingProbe: `Scripts/relay-benchmark-macos.sh apps-1`
3. «Весь трафик»: `Scripts/relay-benchmark-macos.sh full-2`
4. «Выбранные приложения» с RoutingProbe: `Scripts/relay-benchmark-macos.sh apps-2`
5. Отправка, в обоих режимах: `/Applications/RoutingProbe.app/Contents/MacOS/RoutingProbe upload https://speed.cloudflare.com/__up 3`

Цель M4-16 ([SP-3](../features/spikes/SP-3.md)) — по сравнению с «Весь трафик»: один поток не меньше 90 %, несколько потоков не меньше 95 %, CPU расширения на гигабайт не больше 1,25 ×, подключение к имени, уже разрезолвленному через туннель, не дольше +10 мс, ответ DNS не дольше +5 мс, отправка не меньше 90 %, в простое CPU расширения 0 %. Скрипт печатает все эти строки сам.

Ручная проверка M4-10: в режиме выбранных приложений с выбранным браузером загрузить `https://proof.ovh.net/files/1Gb.dat` до конца.

## 7. Секреты после перезагрузки (SP-5, M2-12)

1. Перезагрузить Mac и не открывать Splitway.
2. «Системные настройки › VPN» → включить Splitway (если пунктов Splitway два, подойдёт любой): туннель подключается без приложения, `curl -s https://api.ipify.org` показывает адрес туннеля.
3. Проверить, что приватного ключа нет в настройках VPN. Команда сравнивает начало ключа из твоего `cz-prg.conf` и печатает только число совпадений, ожидается `0`:

```bash
config="путь к cz-prg.conf"
key_prefix="$(awk -F' *= *' '/^PrivateKey/ { print substr($2, 1, 12) }' "$config")"
plutil -convert xml1 -o - /Library/Preferences/com.apple.networkextension.plist | grep -c -F -- "$key_prefix"
```

SIP на Mac включён, поэтому этот прогон закрывает и вопрос SP-5 о поведении с SIP.

## 8. Instruments (по желанию; M4-01, M4-16)

Расширение работает от root, поэтому запись — через `sudo`. Пока идёт запись, в режиме выбранных приложений загрузить файл через RoutingProbe: `/Applications/RoutingProbe.app/Contents/MacOS/RoutingProbe download https://proof.ovh.net/files/100Mb.dat 3`.

```bash
sudo xctrace record --template Allocations --attach "$(pgrep -f network-extension.systemextension | head -1)" --time-limit 60s --output ~/Desktop/splitway-allocations.trace
sudo xctrace record --template 'Time Profiler' --attach "$(pgrep -f network-extension.systemextension | head -1)" --time-limit 60s --output ~/Desktop/splitway-time.trace
```

Записи разберу сам: прислать пути к файлам.

## Что прислать

- Вывод всех скриптов целиком: они не печатают адреса.
- По ручным проверкам — «работает» или «не работает», и если не работает, что видно на экране.
- Если что-то не так — журнал: «Показать журнал» → «Экспортировать журнал». В журнале нет ключей.
- Не присылать: адреса, ключи, снимки экрана с адресами.
