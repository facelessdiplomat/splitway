# SP-10. Mac-приложение в песочнице App Store

| | |
|---|---|
| Статус | закрыт: проверен в тестовой ВМ macOS 26.6.2 (M0-12) 2026-11-02; подпись App Store на нашей сборке проверяется в M7-09 |
| Вопрос | Что ломает App Sandbox, который Mac App Store требует от приложения (решение D-39), и что нужно для подписи App Store |
| Код | ветка `spike/SP-10`, сливается в `master`: правки рабочие, а не прототип |
| Вывод | **Приложение работает в песочнице без временных исключений** после восьми правок; системное расширение остаётся (ADR-15) |

## Как проверяли

- **Песочный зонд.** Утилита командной строки с правом `com.apple.security.app-sandbox`, подписанная ad hoc, со встроенным `Info.plist`: без него утилита в песочнице падает при запуске. Зонд читал в ВМ папки, `Info.plist`, подписи и иконки, а ядро записывало каждый запрет.
- **Сборка разработки Splitway** с правами `com.apple.security.app-sandbox` и `com.apple.security.files.user-selected.read-write`, установленная `Scripts/macos-vm.sh install`. Интерфейс водили через доступность, окна снимали по номеру (`screencapture -l`). Конфигурации — со случайными ключами и адресами TEST-NET. Настоящий туннель не нужен: песочница меняет приложение, а расширение и раньше работало в своей.
- **Подпись App Store** проверялась `codesign -R` на приложении из Mac App Store на этом Mac.
- **Запреты песочницы** — `log show` по сообщениям ядра `Sandbox: Splitway(…) deny`.

## Что исправлено

| Находка | Исправление |
|---|---|
| Требование к клиенту XPC не принимает подпись App Store | ветка `certificate leaf[field.1.2.840.113635.100.6.1.9] exists` вместе с identifier, как в designated requirement приложений из App Store ([SecretDelivery](../SecretDelivery.md)) |
| Значения Network Extension с суффиксом `-systemextension` в Release | убраны: App Store ждёт значения без суффикса |
| Кэш каталога по дате изменения чужих `Info.plist` — API с обязательной причиной, и подходящей причины нет | кэш по `generationIdentifierKey` |
| `~/Applications` не читается | не сканируется; приложения оттуда добавляются кнопкой или перетаскиванием |
| Файл, выбранный в панели, не читается: доступ к нему не открывали | порт `ChosenFileAccess`: доступ открыт, пока собирается идентичность |
| Утилита с Рабочего стола «не исполняемая»: процесс в песочнице не может её запустить | утилита узнаётся по битам права на исполнение |
| «Move to Trash» всегда отказывает | «Show in Finder»: Finder открывает «Программы» с выделенным Splitway, приложение завершается |
| На Mac не видно «Добавить утилиту…» и действий журнала — с песочницей не связано: лист macOS показывает только кнопки закрытия, подтверждения и первое основное действие | кнопки в самом листе ([ApplicationCatalog](../ApplicationCatalog.md), [Diagnostics](../Diagnostics.md)) |

## Вывод

- Mac-приложение работает в App Sandbox без временных исключений, системное расширение остаётся (ADR-15).
- Настройки приложения теперь лежат в его контейнере `~/Library/Containers/com.facelessdiplomat.splitway`, а туннели и журнал — по-прежнему в контейнере группы. Сборок без песочницы не выпускали, поэтому переносить настройки не нужно. В ВМ и на Mac владельца первая сборка в песочнице снова покажет онбординг.

## Не проверено

- Перетаскивание файлов на лист выбора: доступность не умеет перетаскивать.
- Подпись App Store на нашей сборке, ACL элемента System Keychain у переподписанного расширения и установка из TestFlight — M7-09.
- Что App Store Connect примет сборку с этими правами — M7-08.

## Влияние на план

- M7-08: Release-сборка с правами App Store без суффикса; загрузке нужна иконка (M7-13).
- M7-09: на сборке из TestFlight проверить доставку секретов по ветке подписи App Store и ACL System Keychain.
- Новая задача M7-13: иконки приложения нет совсем, а без неё App Store Connect сборку не примет.
